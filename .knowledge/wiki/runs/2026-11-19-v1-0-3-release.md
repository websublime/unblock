# Run — the v1.0.3 release and the v1.0.2 → v1.0.3 live update smoke

## Context

This records the v1.0.3 cut, the PR-M2 step of the `ub-kpe` plan and of `docs/PROCESS.md` §6 and §8. The
fix merged into `release/v1.0.x` as PR #477 (2026-11-19T09:14Z, branch head 19f0ffd); the record before the
cut merged into `main` as PR-M1 #478 (12:14Z). The release commit is `b21c73b` ("release: v1.0.3") on
`release/v1.0.x`. This record is on the branch `v1.0.3-release-record` off `main` b1c653c.

## What & why

These were read rather than restated here: `RELEASING.md` §5 and §6, ci-cd §3.3 and §4, and the `v1.0.3`
subsection of roadmap §1. After the cut, PRD §4 D58 clause (6)(a2) and criterion (n), the health crate
plan, T3.18 and T4.3 of the implementation plan, the roadmap, ci-cd §4 and the published
`docs/roadmap.html` still described v1.0.3 as planned and the `v1.0.2 → v1.0.3` smoke as future. Recording
both closes that drift, as the v1.0.2 record did, and closes `ub-kpe` and `ub-w1j`.

## Outcome

### Before the cut

- fuzz-smoke on `release/v1.0.x` (ruling G5), run 44518979138 at 19f0ffd: all 9 targets green, including
  `content_hash`, where the `ub-y72` flake did not occur. The H3 red path was not needed.
- The `release/v1.0.x` ruleset was missing (GitHub reported no protection). With Miguel's approval ruleset
  27637546 was created per ruling QA5: no deletion or force-push, a pull request required, and the required
  checks `run-report-gate`, `test (workspace)` and `exclusivity (macOS, D29 clause F6)`.

### The releases

- v1.0.3-rc.1 (a13d641): release run 44522869682 was CANCELLED. Four build jobs succeeded and read
  `--package=unblock-cli`, but dist 0.32.0 put `aarch64-apple-darwin` on the retired `macos-14` image, which
  GitHub refused. No GitHub Release was published; the tag stays. Tracked as `ub-ode` and fixed on the
  branch by PR #479 (merged 13:03Z), which pins that triple to `macos-15`.
- v1.0.3-rc.2 (6d41777): release run 44531801963 succeeded; all 5 build logs read `--package=unblock-cli`,
  the pre-release carries 21 assets, and the attestation and SHA256 verified.
- v1.0.3 (b21c73b, tag v1.0.3): release run 44535938580 succeeded; all 5 build logs read
  `--package=unblock-cli`, 21 assets, marked latest. `gh attestation verify` exited 0 for the
  aarch64-apple-darwin and x86_64-unknown-linux-gnu archives, the SHA256 matched, and `unblock version`
  printed 1.0.3.

### The update smoke

`update-smoke.yml` with `from_tag=v1.0.2` and `to_tag=v1.0.3`, dispatched from `main`, became run
44537692027 on 2026-11-19, before any v1.1.0 (ruling K4b).

| triple | where | result |
|---|---|---|

| x86_64-apple-darwin | CI | passed |

| x86_64-pc-windows-msvc | CI | passed |

No leg drew a `403` or `429`, so no hand re-run was needed and the D55 refusal mapping was again not
exercised live.

### What landed

- PRD §4 D58 clause (6)(a2) and criterion (n), the health plan's `src/file_state.rs` row and T4.3's
  out-of-scope entry say the lock loss is fixed in v1.0.3, with the d58 claims rows Q296, Q301 and Q303
  and their header comment moved in the same commit.
- The roadmap status line and §1 heading mark v1.0.3 released 2026-11-19, and the release-path bullet
  records the rc.1 cancellation, rc.2, the final and the smoke; T3.18's acceptance criteria carry the
  result; the `CLAUDE.md` doc map says v1.0.3 is released.
- ci-cd §4 "Runs so far" records the `v1.0.2 → v1.0.3` run.
- `docs/roadmap.html` marks v1.0.3 released in the timeline and on its card.
- The tracker closes `ub-kpe` and `ub-w1j`.

### Measured

`cargo xtask doc-lint`, `cargo xtask knowledge-lint`, `scripts/knowledge/run-report-gate.sh`,
`scripts/knowledge/knowledge-layer-invariants.sh` and every `scripts/checks/*.sh` passed against the final
text.

## Gotchas

- dist 0.32.0 still defaults `aarch64-apple-darwin` to `macos-14`, which GitHub has retired; the job is
  cancelled within a second. `main` has the same exposure, so `ub-ode` stays open until `main` carries the
  `macos-15` pin before any v1.1.0.
- A cancelled rc leaves its tag on origin, and tags are never deleted, so the helper computed rc.2.
- `ub-y72` (the intermittent `content_hash` fuzz failure) did not recur and stays open.
