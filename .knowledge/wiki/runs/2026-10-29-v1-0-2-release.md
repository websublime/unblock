# Run — the v1.0.2 release and the v1.0.1 → v1.0.2 live update smoke

## Context

This records the v1.0.2 cut, a step of `docs/PROCESS.md` §6 and §8. The release commit is `main`
842cdff ("release: v1.0.2"). The record is on the branch `v1.0.2-release-record` off that commit. Solo
session; the pull request is pending.

## What & why

These were read rather than restated here: `RELEASING.md` section 5, ci-cd §4 and the `v1.0.2`
subsection of roadmap §1. After the cut, the roadmap, ci-cd §4 and the published `docs/roadmap.html`
still described v1.0.2 as planned and the `v1.0.1 → v1.0.2` smoke as future. Recording both closes that
drift, as the v1.0.1 record did.

## Outcome

### The releases

- v1.0.2-rc.1 was tagged on 2026-10-28. `release.yml` run 40723533530 succeeded with 21 assets. On an
  aarch64-apple-darwin machine the archive's SHA256 verified, `unblock --version` printed
  1.0.2-rc.1, and `gh attestation verify` exited 0.
- v1.0.2 was tagged on 2026-10-29 at 842cdff. `release.yml` run 40845407897 succeeded on every job with
  21 assets. It is not a pre-release, and `/releases/latest` is v1.0.2.

### The update smoke

`update-smoke.yml` with `from_tag=v1.0.1` and `to_tag=v1.0.2` became run 40846567896 on 2026-10-29.

| triple | where | result |
|---|---|---|
| aarch64-unknown-linux-gnu | CI | passed |
| x86_64-apple-darwin | CI | passed |
| x86_64-unknown-linux-gnu | CI | passed |
| x86_64-pc-windows-msvc | CI | passed |
| aarch64-apple-darwin | CI | failed at `update --dry-run` (v1.0.1 binary, anonymous `403`) |
| aarch64-apple-darwin | by hand | passed |

The CI failure was `{"code":"INTERNAL_ERROR","message":"self-update failed: HTTP status client error
(403 rate limit exceeded) for url (https://api.github.com/repos/websublime/unblock/releases)",
"retryable":false}`, exit 1. That is the `RELEASING.md` §5 step 3 exception. The leg was re-run by hand
on an aarch64-apple-darwin machine with `scripts/release/update-smoke.sh v1.0.1 v1.0.2` and
`AXOUPDATER_GITHUB_TOKEN` set as the workflow sets it. In that run the v1.0.1 `update --dry-run` reported
1.0.2 with the binary byte-identical, and `update` swapped it (sha256 50e413a6… → dde7eccd…). v1.0.2 then
served `--version`, `migrate` and `doctor` on the v1.0.1 workspace. The post-swap `update --dry-run`,
run by v1.0.2 with the token set, exited 0.

### What landed

- The roadmap status line and §1 heading mark v1.0.2 released 2026-10-29, and the token bullet records
  the smoke.
- ci-cd §4 "Runs so far" records the `v1.0.1 → v1.0.2` run.
- `docs/roadmap.html` marks v1.0.2 released in the timeline and on its card, and the token item records
  the smoke.
- `RELEASING.md` is unchanged; no statement in it went stale.

### Measured

`cargo xtask doc-lint`, `cargo xtask knowledge-lint` and every `scripts/checks/*.sh` that CI runs
passed against the final text.

## Gotchas

- The v1.0.2-rc.1 aarch64-apple-darwin build job was cancelled twice with "The job was not acquired by
  Runner of type hosted even after multiple attempts" and a macOS arm64 capacity notice, while
  githubstatus showed Actions operational. It passed on the third attempt after a 20-minute wait.
- The v1.0.1 binary drew the anonymous `403` on the shared macOS runner again, as v1.0.0 did in the
  v1.0.1 run. v1.0.1 never sends the token (`ub-jh5`), so this recurs on every run whose `from_tag` is
  v1.0.1 or older.
- The post-swap query was the first one a token-sending binary sent to GitHub, and it was not refused.
  No `RATE_LIMITED` or `CONFIG_ERROR` path was hit, so the D55 refusal mapping was not exercised live.
- The `ub-bq8` residual was accepted for v1.0.2 (pull request 469); `ub-vcp` was closed by pull request
  468.
