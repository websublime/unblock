unblock = the product = a ground-up, idiomatic **Rust** multi-crate rewrite of the deprecated `beads_rust` tool (binary `br`, "agent-first issue tracker", SQLite + JSONL). Source being studied: `temp/beads_rust-main` (~170k LOC src, ~121k LOC tests).

**Pivot (2026-06-19):** All prior unblock work — an earlier Go/Encore backend, a GitHub-backed control plane, a renderer, and an agentic daemon — was dropped as exploratory and removed from the repo. This supersedes the framing in earlier planning notes.

**Locked decisions:**
- Storage = **libsql** (Turso SQLite fork). Same async client gives local-only OR embedded-replica/`new_synced_database` remote sync — so NO separate "shared service" is needed.
- MCP = **rmcp** over **stdio** (async-first on tokio; `#[tool_router]`/`#[tool]` macros; uses schemars, which beads already uses).
- Errors = **snafu** (per-crate error enums, not a god-enum; map to rmcp ErrorData at the boundary).
- **MCP-first**: all domain features exposed via MCP tools/resources/prompts; CLI dropped as feature surface (open: keep a minimal lifecycle/ops CLI — serve/migrate/doctor/version).
- Adopting rmcp + libsql ⇒ the whole stack goes **async (tokio)**.
- MCP-only sheds the rich-rendering stack: rich_rust, toon_rust/tru, crossterm, indicatif.
- Everything renamed to `unblock`.

**Sync model — RESOLVED (2026-06-19, option B):** libsql is the source of truth (local file; remote/replica available later). Keep a LIGHT JSONL import/export as an optional feature (portability/audit/git-diff); DROP the heavy git-merge coordination (3-way merge, 4-phase collision detection, .write.lock/.sync.lock, data-loss guards). `unblock-sync` shrinks from ~9.4k LOC to a simple JSONL↔DB converter. Reversible toward "DB-only" (option A) later. This is a product-identity shift away from beads' "serverless, lives-in-git" thesis — accepted deliberately.

**Crate plan (from PRD discovery workflow, adapted to unblock-* + MCP-first):** unblock-model (pure types) · unblock-error (snafu, NOT thiserror) · unblock-policy (scheduler/coordination/gates, pure) · unblock-storage (Storage trait + libsql impl) · unblock-sync (light JSONL converter) · unblock-health · unblock-config · unblock-engine (shared session lock→open→mutate→flush, consumed by BOTH mcp and cli) · unblock-render (reduced — MCP-only makes rich TTY rendering mostly vestigial; rich_rust replacements likely unneeded) · unblock-mcp (PRIMARY, rmcp) · unblock-cli (reduced to lifecycle: serve/migrate/doctor/version) · unblock-fuzz. Acyclic layering: model/error → policy → storage → sync/health → config → engine → mcp/cli.

**Discovery dossier:** 25 FRs, 17 NFRs, 11 domain entities. Source had a ~50k-LOC monolith binary crate; monster files storage/sqlite.rs ~22.6k LOC, sync/mod.rs ~9.4k, doctor.rs. fsqlite defect 243 = 100% CPU hot-spin on lock contention (why we leave it). Preserve the agent contract: --json/--robot always-valid JSON, structured errors (code/message/hint/retryable), 0-8 exit-code taxonomy, atomic --claim, ready/close --suggest-next, capabilities/robot-docs/schema versioned by contract_version.
