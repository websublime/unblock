name: feedback-implementer-probe-must-include-cargo-fmt
description: unblock local/Verify probe MUST mirror the FULL CI job set, not a `-p <crate>` subset: include `cargo fmt --check`, `cargo xtask doc-lint`, `cargo xtask check-layering`, AND workspace-scoped `cargo test --workspace` / `insta --check` — clippy/`-p crate` tests do NOT cover them
type: gotcha
---

The `unblock` CI has a **standalone `fmt` job** (`cargo fmt --check`) separate from `clippy (pedantic)`. Passing clippy does NOT imply fmt-clean.

**Why:** On T1.4 ([unblock#380](https://github.com/websublime/unblock/pull/380)) the implementer + fix agents ran `cargo clippy`/`test`/`insta` (all green) but the verification probe written for them did NOT list `cargo fmt --check`. CI then failed on `fmt` alone — rustfmt re-wraps method chains + struct literals in the new test helpers. Cost: an extra `style(test): apply cargo fmt` commit + push + CI re-run.

**How to apply:** every implementer/Verify-gate prompt's cargo probe list for this repo MUST include `cargo fmt --check` (or `cargo fmt` then commit) alongside `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --locked`, the `-p unblock-storage --features testkit` suites, `cargo insta test --check`, **`cargo xtask doc-lint`**, and **`cargo xtask check-layering`**. Mirrors the **11 CI jobs**. A probe scoped to `-p <crate>` (e.g. `cargo test -p unblock-render`) is NOT enough — it skips doc-lint and any other crate's tests.

**CAPTURE the probe correctly (2026-07-21, ub-lp9.15).** Running the right jobs is not enough — a probe once piped the test section through `tail -25` and reported the exit code of a trailing `echo`, which showed "5 tests passed" + exit 0. That is a **green verdict resting on ~0.4% of the suite**. `cargo test --workspace` here is **~113 suites / ~1366 tests**; if a summary shows a two-digit test count, the capture is broken, not the suite. Redirect each job to its own log and capture `$?` **immediately** (`cmd > /tmp/x.log 2>&1; echo "exit=$?"`) — `PIPESTATUS` does not survive this shell reliably, and a `tail` in the pipeline masks everything above it. A truncated probe that *looks* green is worse than a red one.

**T2.1 follow-on (2026-06-29, [unblock#385](https://github.com/websublime/unblock/pull/385)):** `cargo xtask doc-lint` is BOTH a standalone CI job AND wired as `xtask/tests/doc_lint_corpus.rs::real_corpus_is_green`, which runs INSIDE `cargo test --workspace` and `cargo insta test --check`. So a single doc-lint violation fails **three** CI jobs at once (doc-lint + test workspace + snapshots). This bites hand-written status-doc edits too — any linted corpus doc is not exempt just because it was hand-edited. **doc-lint class [e] (cross-ref):** a bare `§N` must be qualified by a recognized doc token **immediately before** it — only `spine` / `PRD` / `impl-plan` / `roadmap` / `ci-cd` (or the full `*.md` filenames) resolve; any `unblock-*` or other `*.md` token is a carry-forward **barrier** that breaks inheritance (so `crates/unblock-render.md §5` does NOT resolve — drop the `§` or use a recognized qualifier). Run `cargo xtask doc-lint` after ANY edit to a corpus doc before committing. See [[project-background-agent-crash-recovery]] for the recovery flow when an implementer is interrupted.
