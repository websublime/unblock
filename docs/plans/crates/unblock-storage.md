## 1. Purpose / Layer / Depends-on

- **One-line purpose:** Define the backend-agnostic async `Storage` trait and provide the **only** backend-aware implementation (libsql), owning schema, migrations, prepared queries, transactional mutate (rows + audit events together), WAL + native `busy_timeout` non-spin discipline (NFR-3), and the remote/replica path behind a non-default feature (D15).
- **Layer:** L2.
- **Depends on (acyclic, NFR-15 / spine §0):** `unblock-model` (L0) + `unblock-error` (L0) **only**. NOT `unblock-policy` (CF-11 fix — the engine at L5 composes storage + policy; any contract type both need lives in `unblock-model`, e.g. `CacheKey`). NOT `tracing` for domain logic beyond the `unblock.reliability` target seam. Backend crate (`libsql`) is a **private** dependency: no libsql type may appear in any public signature (spine §6 rule 2; libsql errors absorbed into `StorageError::Backend { source: BackendOpaque }`).
- **Invariant gates this crate owns:** RK-1 / NFR-3 contention lab (M0 exit gate, before any crate depends on storage); NFR-16 backend-independent `Storage` contract suite; RK-4 (remote feature keeps TLS/HTTP off the default build — verified by `cargo-deny` on the default feature set).

## 5. Open questions specific to this crate

- **OQ-1 (search backend) — RESOLVED (T0.6, Miguel):** v1 reproduces the original's `instr(lower(col))` **substring** scan over title+description+id (sqlite.rs:4663–4669) — not a LIKE-over-title scan; the `text_contains` FILTER keeps `LIKE ? ESCAPE '\'`. FTS5 stays a v1.4 perf option (availability in bundled libsql to be confirmed then). **Do not simplify away** — flag for Miguel if the substring scan misses the NFR-1 search budget.
- **OQ-2 (busy_timeout value) — RESOLVED (T0.6, Miguel; CONFIRMED at T0.8):** `BUSY_TIMEOUT_MS = 5000` native (`Connection::busy_timeout`). The T0.8 contention lab **confirmed 5000ms holds** — measured `R ≈ 1.05` (honest blocking; sleep-based, never spins), with the forced-spin `busy_timeout=0` control measured at `R ≈ 27` on this 14-core box (`R ≈ 4.42` on a 4-vCPU runner) proving the metric detects a spin via its core-independent busy-retry + CPU-burn signature. No re-tune; 5000ms is the locked baseline (the sanctioned inverse of beads's `=0`/backoff).
- **OQ-3 (ready ordering ownership) — RESOLVED (T1.1, Miguel; spine §4.1 normative pin + policy Q1):** storage `ready_issues` returns the unblocked+undeferred candidate set deterministically **pre-sorted by the index** — `ORDER BY priority ASC, created_at ASC, id ASC` (matching `idx_issues_ready`, stable for NFR-14 snapshots); the **engine** re-ranks via `unblock-policy::cmp_ready` — the source-faithful **bucket hybrid** (`ready_hybrid_bucket(priority.0<=1)` ASC, created_at ASC, id ASC; `sqlite.rs:10444`/`10515`) — to produce the final order (CF-11). Storage **never imports policy**. Note the SQL pre-sort (full priority order) is **not** identical to `cmp_ready` (which buckets P0/P1 together), so the engine re-rank can reorder relative to the SQL — this is intended, not a second redundant sort of an already-final order. Any re-sort cost at scale is a T3.5 perf concern (the comparator is O(1) per pair, negligible vs the query), not a storage-ownership question.
- **OQ-7 (contract-type ownership) — RESOLVED (CF-A/CF-B/CF-C, spine §1.10):** `ListFilters`, `CountGroupBy`, `CountBucket`, `GraphEdge`, `DepTree` are now defined normatively in `unblock-model` (spine §1.10) and **re-exported** from this crate; storage defines only `DeletePlan`/`DeleteMode`/`IssuePatch`. Rationale: unblock-policy needs `ListFilters` for its filter-fingerprint but must not depend on storage, and unblock-render (model+error only) must format `CountBucket`/`DepTree`. Layering unchanged — types moved *down* to L0 model; storage still depends on model+error only. `DiagnosticKind`/`DiagnosticReport` likewise live in model (spine §1.10, CF-B) and back the CF-E diagnostic-probe seams.
- **OQ-4 (blocked/ready cache) — RESOLVED (T0.6):** the original `blocked_issues_cache` table is **dropped**; blocked/ready are computed **live** — the cache JOIN/NOT-IN is replaced by the live blocked-set computation (direct 3-type blockers + open epic-rollup children + transitive children of blocked parents) and `ready = candidates − blocked`. **Perf re-confirm re-homed to T3.5** (not T0.8 — the contention lab asserts no throughput/latency budget, only non-spin + correctness): re-confirm the live path meets the ready 10k <50ms budget (NFR-1) at 250k (NFR-2) in the **T3.5 `benches/storage.rs` criterion** suite; if it misses, reintroduce a projection table in v1.4 (additive), not v1.
- **OQ-5 (pool vs single connection under D14) — RESOLVED (T0.6, Miguel + design Review): TWO connections.** `LibsqlStorage` holds a serialized **write** conn (mutations via `BEGIN IMMEDIATE`; the engine's D14 `Semaphore` serializes writers at L5) **and** a separate **read** conn (WAL MVCC reader snapshots vs the writer, FR-10), both from one `libsql::Database`. `open_in_memory()` uses a named shared-cache URI (`file:<unique>?mode=memory&cache=shared`) so both conns see the same in-memory DB — this path is **shared-cache, NOT WAL** (in-memory cannot WAL, so the WAL pragmas are skipped there). The intermittent parallel-open flake observed on this path is **not** the WAL-skip but the `SQLite` shared-cache **global-open race** — root-fixed at T0.9 by serializing the in-memory open via `memory_open_lock` (see `libsql/mod.rs`). Real WAL + busy_timeout concurrency is validated by the **T0.8 contention lab on a FILE DB**. Public API (`open_local`/`open_in_memory`) is unchanged.
- **OQ-6 (multi-writer reconciliation, v1.2):** last-write-wins on `content_hash` vs operation log for remote sync (roadmap §3 risk) — a v1.2 design decision that lands in `remote.rs`; do not pre-bake into v1 schema beyond reserving room.
