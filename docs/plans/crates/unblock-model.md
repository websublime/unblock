# unblock-model — File-level Plan

- **Status:** DRAFT — for review. Conforms to `docs/plans/01-design-spine.md` §1 (AUTHORITATIVE) and `docs/PRD.md` §7/§8.1. **Source of truth: PRD APPROVED v1.1.**
- **Date:** 2026-06-19
- **One-line purpose:** Pure domain types + content-hash / sync-equality / tombstone semantics / validation / shared contract types. **No I/O, no async, no backend.**
- **Layer:** L0 (leaf).
- **Depends on:** `unblock-error` only (for `ModelError` as the `FromStr` / validation error type). External crates: `serde`, `serde_json`, `chrono`, `schemars`, `sha2`; `std::path::PathBuf` (used by `ExportReport`, spine §1.10). **Nothing above L0.** (Spine §1: "Pure types, no I/O"; PRD §8.1: `unblock-model` depends on `—`. We take the single in-workspace edge `model → error` because the spine declares `FromStr::Err = unblock_error::ModelError` and `IssueValidator::validate -> Result<(), unblock_error::ModelError>`. This keeps L0 acyclic: `error` itself depends on nothing in-workspace, so `model → error` introduces no cycle. **Open question Q1** flags the alternative.)

> Acyclicity note: `model` and `error` are both L0. The spine pairs them (`L0 model | error`) and routes model's `FromStr`/validation errors through `unblock_error::ModelError`. Since `unblock-error` has no in-workspace dependencies, the edge `model → error` is safe and is the only in-workspace dependency this crate has across **all** versions.

## Public API summary (what other crates import), per version

### v1 (LOCKED — M0 / T0.3, spine §1)
- **Enums:** `Status`, `Priority`, `IssueType`, `DependencyType`, `EventType` (all open enums with `Custom(String)` tail; `as_str` / `Display` / `FromStr`; the const predicate helpers per spine).
- **Structs:** `Issue` (full field set, spine §1.6), `Dependency`, `Comment`, `Event`, `EpicStatus` (the last two/`Comment` are types-defined-now, populated `[v1.1]`).
- **Behaviour:** `Issue::compute_content_hash`, `Issue::sync_equals`, `Issue::is_expired_tombstone`, tombstone constructor/predicate helpers.
- **Validation:** `IssueValidator::validate(&Issue) -> Result<(), unblock_error::ModelError>`.
- **Shared contract type:** `CacheKey(pub String)` (CF-11 — needed by both `policy` and `storage`, so it lives here).
- **Query/result contract types (spine §1.10):** `ListFilters`, `CountGroupBy` (CF-C — `policy` needs `ListFilters` for its filter-fingerprint but cannot depend on `storage`); `CountBucket`, `GraphEdge`, `DepTree`, `CloseOutcome`, `ImportReport`, `ExportReport` (CF-A — display/result DTOs `render` (model+error only) must format); `DiagnosticKind`, `DiagnosticReport`, `DiagnosticFinding` (CF-B — referenced by engine/render/mcp, defined normatively here); `OutputFormat` (CF-J — `Json` (default) `| Robot | Plain | Csv | Markdown`, `Toon` feature-gated behind the `toon` feature; needed by both `render` and `config`, so it is owned here once). These are **owned here** and **re-exported** by `unblock-storage`/`unblock-engine` (and `unblock-render`/`unblock-config` re-export `OutputFormat`); they do not redefine them. **Derive policy (spine §1.10, normative):** every one of these 12 cross-crate DTOs derives the full set `Debug, Clone, Serialize, Deserialize, JsonSchema` (plus `PartialEq, Eq` where round-tripped) so they can flow through MCP `ToolOutput`/`QueryInput`, engine results, and render parse-back; `DiagnosticFinding` is included so consumers reaching it via `DiagnosticReport` re-exports compile (G-10). `PathBuf` (`ExportReport.path`) maps to a `JsonSchema` string.
- **Serde helper fns** referenced by `#[serde(...)]` attributes (`is_false`, `serialize_compaction_level`, `deserialize_optional_metadata`) — `pub(crate)`.

### v1.1 (LOCKED — additive only; no breaking changes)
- `Comment` / `EpicStatus` become *populated* (no type change; consumers gain real data via storage/engine).
- `Issue.comments` populated; `EventType::{LabelAdded, LabelRemoved, Commented}` exercised (variants already exist in v1).
- New rollup helper: `EpicStatus::is_eligible_for_close(...)` derivation lives in `policy`/`engine`, but the **derived-input shape** (`EpicStatus`) stays here. No new public types expected; if a label-rename or saved-query needs a shared type, it is added additively.

### v1.2 (PROPOSED — `◐` per roadmap §7; "only if a sync-state type or error variant is needed")
- *Conditional:* a `SyncState` / `ReplicaMeta` marker type **iff** remote/replica sync (D15→GA) needs a model-level shape both `storage` and `sync`/`health` share. Additive newtype, feature-neutral (no network types — those stay in `storage`).

### v1.3 (PROPOSED — `◐`; "activate compaction fields as a real archival path", roadmap §4)
- Compaction fields (already present since v1 for JSONL fidelity, D12) gain **active** helper methods: `Issue::is_compacted`, `Issue::compaction_summary`, and `sync_equals`/round-trip property coverage extended to compacted issues. No new fields (fields reserved in v1); only behaviour + helpers.

## Open questions specific to this crate

- **Q1 — `model → error` edge. [RESOLVED — keep `model → error`.]** The amended spine (§1.1–§1.9, AUTHORITATIVE) routes `FromStr::Err` and `IssueValidator::validate` through `unblock_error::ModelError`, and the §1.10 relocations only moved types *down* into model (no new edge). `unblock-error` is dependency-free in-workspace, so `model → error` introduces no cycle and is the sole in-workspace edge across all versions. Decision: keep the edge as the spine specifies; do **not** define a local `ModelError`. (PRD §8.1's literal "Depends on: —" is reconciled by treating `error` as a co-leaf the spine pairs with `model`.)
- **Q2 — Validation error shape.** Original `IssueValidator::validate` returns `Result<(), Vec<ValidationError>>` (collects all failures). The spine signature is `Result<(), unblock_error::ModelError>` (single error). Decide: single first/most-severe `ModelError`, or a `ModelError` variant carrying a `Vec` of field errors (better agent hints, FR-11). Recommendation: a `ValidationFailed { fields: Vec<FieldError> }`-style variant in `unblock-error` so the boundary can still emit one `ErrorCode` while preserving multi-field detail. (Needs an `unblock-error` plan agreement.)
- **Q3 — v1.2 `sync_state.rs`.** Conditional file. Confirm at v1.2 design whether any sync/replica shape must be shared between `storage` and `sync`/`health` (⇒ lives here, model) or stays internal to `storage` (⇒ this file is never created). Default: do not create until proven needed.
- **Q4 — Go-bd hash padding fields.** `content_hash_from_parts` hashes ~17 Go-bd zero-value placeholder fields for byte-compat. For a clean rewrite with a one-shot `bd` import (FR-26/D16), confirm we keep the full padding (required for idempotent re-import dedup against `bd`-exported hashes) vs. drop it (cleaner, but breaks `bd` content-hash parity). Recommendation: **keep** for v1 (FR-26 idempotency AC depends on it); revisit dropping it post-`bd`-migration in a later version.
- **Q5 — `Custom` variant validation.** Should `Status::Custom`/`IssueType::Custom`/`DependencyType::Custom` be length/charset-validated in `IssueValidator` (original caps custom variants at 50 chars), and should an unknown enum on a write path be a soft-accept (open enum) or a `ValidationFailed`? Recommendation: open-enum accept on read/deserialize; length-cap-validate on the create/update write path via `IssueValidator`.
