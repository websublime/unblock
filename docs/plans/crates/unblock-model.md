# unblock-model — File-level Plan

- **Status:** DRAFT — for review. Conforms to `docs/plans/01-design-spine.md` §1 (AUTHORITATIVE) and `docs/PRD.md` §7/§8.1. **Source of truth: PRD APPROVED v1.1.**
- **Date:** 2026-06-19
- **One-line purpose:** Pure domain types + content-hash / sync-equality / tombstone semantics / validation / shared contract types. **No I/O, no async, no backend.**
- **Layer:** L0 (leaf).
- **Depends on:** `unblock-error` only (for `ModelError` as the `FromStr` / validation error type). External crates: `serde`, `serde_json`, `chrono`, `schemars`, `sha2`; `std::path::PathBuf` (used by `ExportReport`, spine §1.10). **Nothing above L0.** (Spine §1: "Pure types, no I/O"; PRD §8.1: `unblock-model` depends on `—`. We take the single in-workspace edge `model → error` because the spine declares `FromStr::Err = unblock_error::ModelError` and `IssueValidator::validate -> Result<(), unblock_error::ModelError>`. This keeps L0 acyclic: `error` itself depends on nothing in-workspace, so `model → error` introduces no cycle. **Open question Q1** flags the alternative.)

> Acyclicity note: `model` and `error` are both L0. The spine pairs them (`L0 model | error`) and routes model's `FromStr`/validation errors through `unblock_error::ModelError`. Since `unblock-error` has no in-workspace dependencies, the edge `model → error` is safe and is the only in-workspace dependency this crate has across **all** versions.

> **`Cargo.toml` features.** `[features]` carries `toon = []` — a **bare marker feature** (CF-J / spine §1.10) that toggles only the `#[cfg(feature="toon")] Toon` variant of `OutputFormat`. The model crate has **no toon encoder** (encoding lives in `unblock-render`); the feature exists here solely so the shared `OutputFormat` enum reserves the variant for `render`/`config` to re-export. The default (no-`toon`) feature set is the snapshot baseline for `tests/schema_snapshots.rs`. `default = []`. Dev-deps: `insta`, `proptest`, `criterion`; `[[bench]]` entries `hash` and `sync_eq` (`harness = false`, informational — not NFR-1 CI gates).

## Open questions specific to this crate

- **Q1 — `model → error` edge. [RESOLVED — keep `model → error`.]** The amended spine (§1.1–§1.9, AUTHORITATIVE) routes `FromStr::Err` and `IssueValidator::validate` through `unblock_error::ModelError`, and the §1.10 relocations only moved types *down* into model (no new edge). `unblock-error` is dependency-free in-workspace, so `model → error` introduces no cycle and is the sole in-workspace edge across all versions. Decision: keep the edge as the spine specifies; do **not** define a local `ModelError`. (PRD §8.1's literal "Depends on: —" is reconciled by treating `error` as a co-leaf the spine pairs with `model`.)
- **Q2 — Validation error shape. [RESOLVED — D-E1, aggregate carrier.]** Original `IssueValidator::validate` returns `Result<(), Vec<ValidationError>>` (collects all failures); the spine signature is `Result<(), unblock_error::ModelError>` (single error). Resolution: `unblock-error::ModelError` carries the **`ValidationFailed { fields: Vec<FieldError> }`** aggregate variant (D-E1, spine §2.1) — `validate` collects ALL failures into that one variant, so the boundary still emits exactly one `ErrorCode` (`VALIDATION_FAILED`) while preserving every failing field (surfaced as `context["fields"]`, spine §2.4). The §1.9 signature stays VERBATIM (the aggregate lives inside the single `ModelError`). Scalar `ModelError` variants remain for the single-field `FromStr` paths (`InvalidStatus`/`InvalidPriority`/`InvalidType`/`InvalidId`) and the empty/whitespace-title `RequiredField` case.
- **Q3 — v1.3 `sync_state.rs`.** Conditional file. Confirm at v1.3 design whether any sync/replica shape must be shared between `storage` and `sync`/`health` (⇒ lives here, model) or stays internal to `storage` (⇒ this file is never created). Default: do not create until proven needed.
- **Q4 — Go-bd hash padding fields. [RESOLVED — KEEP (Miguel + design-Review gate).]** `content_hash_from_parts` hashes the 17 Go-bd zero-value placeholder fields for byte-compat, and we **KEEP** the full padding in v1 (FR-26/D16 idempotent one-shot `bd` import depends on byte-for-byte content-hash parity with `bd`-exported hashes). The frozen tail (exact order, appended after `is_template`) is now documented normatively in **spine §1.8** and locked by the golden `insta` snapshot in `tests/golden_hash.rs`. Ported `util/hash.rs` L110–129 verbatim. Revisiting/dropping it is a post-migration future-version decision and a breaking change (spine amendment required).
- **Q5 — `Custom` variant validation. [RESOLVED — 50-char cap on `Status::Custom` + `IssueType::Custom` ONLY (Miguel + design-Review gate).]** Unknown enum strings are **soft-accepted** on deserialize (open enum). On the validation path, `IssueValidator` caps `Status::Custom` and `IssueType::Custom` at `CUSTOM_VARIANT_MAX_CHARS = 50` (`chars().count()`); **`DependencyType::Custom` is NOT capped** (it has no validator hook — `DependencyType` is validated structurally in `storage`, not field-length-capped here). A cap breach is a `FieldError` row (`field: "status"` | `"issue_type"`) inside the aggregate `ValidationFailed`, never a hard deserialize failure.
