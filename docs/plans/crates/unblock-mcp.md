## Pinned rmcp 1.7 API contract (the build-against surface — RK-2; resolves OQ-1/OQ-2)

All facts below are **READ FROM VENDORED SOURCE** (`rmcp-1.7.0` / `rmcp-macros-1.7.0`), not memory — they replace the OQ-1/OQ-2 uncertainty with the confirmed contract. They are the normative shape this crate builds against; the `#![forbid(unsafe_code)]` invariant holds (nothing in the rmcp surface we touch needs unsafe).

- **Tool/prompt macros.** `#[tool]` / `#[tool_router]` / `#[tool_handler]` (and `#[prompt]` / `#[prompt_router]` / `#[prompt_handler]`) — methods on `&self`. `#[tool_router]` generates `Self::tool_router() -> ToolRouter<Self>`; `#[tool_handler]` wires `call_tool`/`list_tools` + a `get_info().enable_tools()`. Routers compose via `Add`/`merge`; rebuild-per-call is fine (schemas are cached per `TypeId`), so storing the router in a field is optional.
- **Typed args via the `Parameters<T>` extractor.** A tool/prompt fn takes `Parameters(args): Parameters<T>` where `T: rmcp::schemars::JsonSchema + serde::Deserialize`. The per-tool input schema is the draft-2020-12 `JsonSchema` of `T`; bad args → `ErrorData::invalid_params`. **`schemars` is pinned via the `rmcp::schemars` re-export** so the derive macro and rmcp see the identical schemars version (workspace `schemars = "1"` matches rmcp 1.7).
- **`ServerHandler`.** `trait ServerHandler: Sized + Send + Sync + 'static` — **all 26 methods are provided, ZERO are required**, and `impl ServerHandler for Arc<T>` exists. So the handler holds `Arc<Session>` and is itself Send+Sync. Capabilities are advertised by overriding `get_info()` → `ServerCapabilities::builder().enable_tools().enable_prompts().enable_resources()`.
- **Resources — NO macro, NO router, NO URI-template matcher.** rmcp's `resource.rs` is EMPTY. `ResourceTemplate`/`RawResourceTemplate::new(uri_template, name)` exist to *advertise* the `unblock://issues/{id}` string, but rmcp routes `read_resource` by the raw `params.uri: String` only — there is no built-in `{id}` extractor. Therefore we **HAND-WRITE `get_info()`** (to add `.enable_resources()`) plus `list_resource_templates`/`read_resource`, and **HAND-PARSE `{id}` from `params.uri`** (strip the `unblock://issues/` prefix); an unmatched/unknown uri → `ErrorData::resource_not_found` (`-32002`). (Because resources have no handler macro, `get_info` cannot be macro-generated alongside tools+prompts: stack `#[tool_handler]` + `#[prompt_handler]` + the hand-written resource methods on ONE `impl ServerHandler`, do NOT use `#[tool_router(server_handler)]`, and do NOT let two macros both emit `get_info` — write it once by hand.)
- **In-band domain-error channel (resolves OQ-2).** `CallToolResult::structured_error(json)` carries `content` (a text mirror) + structured `data` + `is_error = Some(true)` in ONE result — i.e. a single call can return valid-JSON content AND `isError=true` AND structured `data`. **Domain errors → in-band `structured_error`** (FR-11, always-valid-JSON). `Err(ErrorData{code,message,data})` is reserved for **true protocol faults** (transport/serialization/auth-level) only.
- **stdio + cooperative shutdown (FR-17, resolves OQ-1 transport).** `handler.serve_with_ct(rmcp::transport::stdio(), ct).await?.waiting().await?`, where `ct` is rmcp's plumbed-through `tokio_util::sync::CancellationToken`; a SIGINT/SIGTERM handler calls `ct.cancel()` to drain in-flight and return cleanly. (`transport::stdio()` needs the `transport-io` feature ✅. **Add `tokio-util = "0.7"` to the crate deps** for the token.)
- **Quotas have NO rmcp hook (NFR-18).** rmcp provides NO built-in request-size / array-length / string-length / per-tool-concurrency / batch cap on the stdio path, and there is no middleware layer for stdio (the `tower` layer is streamable-HTTP only). Therefore the `Quotas` limits MUST be enforced by a shared `enforce_quota(&args)` preflight **INSIDE each tool body** — after `Parameters<T>` deserialization and BEFORE any `Session` call — returning an in-band error on breach. (Per-workspace write serialization stays the `unblock-engine` tokio `Semaphore`, D14 — rmcp gives no write lock.)

### Confirmed adapter facts (F-4/F-5/F-6 + the wire/seam notes — pinned for build)

- **F-4 — `SyncOutput`/`IdOnly`/`Capabilities` are mcp-owned.** They exist NOWHERE in any other crate; spine §5.3/§5.4 define them in the mcp section. This crate **DECLARES** them locally (`IdOnly{ id }`, `SyncOutput::{Export(ExportReport)|Import(ImportReport)}`, `Capabilities{…}`) — it does NOT re-export them from `unblock-model`. (`ExportReport`/`ImportReport` themselves ARE model spine §1.10 DTOs, sourced from `unblock-model`.)
- **F-5 — `CONTRACT_VERSION` is the mcp-owned SSOT** (`src/options.rs`), disjoint from policy's `POLICY_CONTRACT_VERSION`. It is the sole MCP `contract_version` source (surfaced in `Capabilities` + the `diagnostics version` finding). **T2.6/D25 — the gate is ONE pinned hash:** **`CONTRACT_HASH`** (superseding `SCHEMA_BUNDLE_HASH`) = SHA-256 over `serde_json::to_vec(&(capabilities(), schema_bundle()))` — the ordered two-document tuple, covering the 7 per-tool `{input, output}` schemas + the shared in-band error schema AND the tool/resource/prompt descriptors + the full error-code map incl. `hint_shape`. Both documents embed `contract_version`, so the gate is non-vacuous in both directions (D22 mechanism): any content edit — a tool input OR output schema, a capabilities-document descriptor string, an `unblock-error` `ErrorCode`-set or hint-shape change — forces a `CONTRACT_VERSION` bump + a re-pin + a golden re-bless; a bump without a real change moves the digest and is equally caught. The two insta goldens (`contract_suite__capabilities.snap`/`__schema_bundle.snap`) localize WHICH document moved. **Golden-only (NOT version-coupled): the 3 prompt rendered-message insta snapshots** — prompt content re-blesses deliberately without a bump; the prompt SET/NAMES are version-coupled (live-vs-builder parity + hash); prompt DESCRIPTION strings are version-coupled only in their capabilities-document copies. History: `unblock.mcp.v1` (T2.2) → `v1.1` (T2.3/D22, `issue` input schema) → `v1.2` (T2.6/D25, outputs + capabilities enter the gate — this REVERSES the PRD D24 clause-3 forward rule: an output-DTO change now moves the gate; the T2.5 no-bump ruling stays historically valid).
- **F-6 — error mapping routes through the spine §2.4 sanitization chokepoint.** `engine_error_to_structured` is exactly `(&engine_err).into()` (the blanket `From<&EngineError> for StructuredError`; `EngineError` is `snafu::Snafu` + `CodedError`, all variants covered) → an already-sanitized `StructuredError` → `to_rmcp_error_data` — the RESOURCE-boundary mapper (T2.6/F-2): `ErrorCode::IssueNotFound` (a missing `{id}` or an unknown URI) → `ErrorData::resource_not_found` (-32002, the pinned rmcp contract above); every other code → `INTERNAL_ERROR` (-32603); the full structured payload rides `data` on both arms. The JSON boundary makes `context` terminal-safe (serde escapes it) — **no extra sanitize needed at this JSON boundary** (unlike render's text formats, which do sanitize context values).
- **Adapter — `diagnostics` tool → `Session::diagnostics(kind)`, NOT `Session::doctor`.** The spine §5.1 `diagnostics` tool's 7 kinds map to the BUILD-now `Session::diagnostics(kind)` (the 7-kind read path, pure-DB). It must NOT route through `doctor()`/`recover()` (the T3.3 health seam, which returns `FeatureNotWired{"health"}`). See the spine §4.1 precision note.
- **Adapter — `Changelog{since}` drops `since` pre-call.** The wire field is accepted (do not error) but has no `Session` parameter at T2.2; `since` threading is T2.7. `Session::diagnostics(Changelog)` uses the full window today.
- **Wire — two keys for the same `DependencyType` enum.** `Dependency.dep_type` serializes as `"type"` (`#[serde(rename = "type")]`) while `GraphEdge.dep_type` is NOT renamed (serializes as `dep_type`). Both keys are EXPECTED in the contract goldens (`DepOutput::Deps` under `"type"`; `Tree`/`graph` `GraphEdge` under `dep_type`).

### Scope note — Option A (T2.2 lands the full crate; T2.3 is the AC-proving sibling)

Under **Option A** (the M1 T1.2→T1.4-T1.7 precedent), **T2.2 lands the FULL crate surface** in one coherent reviewable unit: the rmcp stdio server + `ServerHandler` (holding `Arc<Session>`) + all **7 tools** (issue/claim/defer/query/dep/sync/diagnostics) wired to `Session` + **5 resources** + **3 prompts** + error mapping (FR-11) + the NFR-18 quotas-preflight infra (`enforce_quota`) + the capabilities/schema builders (FR-12) + cooperative shutdown via `serve_with_ct` (FR-17) + **the M2 lifecycle exit-gate** e2e `query{ready}→claim→close` (`tests/lifecycle.rs`). - **OQ-2 (in-band vs. protocol error) — RESOLVED (T2.2).** A single `CallToolResult::structured_error(json)` carries content + structured `data` + `is_error=Some(true)` together — domain errors flow **in-band** as `structured_error` (always-valid-JSON, FR-11); `Err(ErrorData)` is reserved for true protocol faults. See the "In-band domain-error channel" pin above.
- **OQ-3 (label rename/list-all placement) — DEFERRED to v1.1.** Do label `rename`/`list_all` ride the `issue` tool (an `action`) or `query` (a `kind`)? Affects which file grows and the v1.1 `contract_version` bump. Lean: `query kind: labels` for reads, `issue action: relabel` for the rename mutation — decided before the v1.1 build, no T2.2 action.
- **OQ-4 (gates surface) — DEFERRED to v1.1.** Are workflow-gate verdicts (FR-19) enforced inside `issue.update` status transitions (returning `PolicyViolation`), or exposed as a separate `query kind: gates` read? The former keeps the tool count flat (RK-3) and matches "gates block transitions"; confirmed with the policy owner before the v1.1 build, no T2.2 action.
- **OQ-5 (read-snapshot cache) — RESOLVED (T2.2): OMIT at L7 in v1.** The original `mod.rs` `McpReadSnapshotCache` cached read JSON keyed by a db/wal/jsonl mtime witness; with libsql WAL + the engine read fast path (FR-10) we omit the L7 read cache in v1. Revisit only if NFR-1 `ready` budgets need it at T3.5.
- **OQ-6 (new transports, v2+) — RESOLVED (T2.2): DEFER new transports.** Roadmap §5 lists HTTP/SSE as a later direction under the same isolation discipline (D2 locks stdio primary). The `serve()` signature is already transport-agnostic, so we do NOT pre-build a `src/transport/` seam now; defer entirely.
