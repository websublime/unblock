# unblock-engine — File-level Plan

- **Status:** DRAFT — for review. Conforms to `docs/plans/01-design-spine.md` §4 (authoritative) + `docs/plans/00-roadmap.md` + `docs/PRD.md` (PRD APPROVED v1.1). Where this file and the spine disagree, the spine wins; amend the spine first.
- **Date:** 2026-06-19

## Purpose / Layer / Depends-on

- **One-line purpose:** The single mutation home (FR-9) — a `Session` that **consumes a `WorkspaceContext` built by `unblock-config`** (CF-D: config performs `.unblock/` discovery, opens/migrates libsql, and builds the `Arc<dyn Storage>`; the engine does **not** construct storage itself) and composes storage + policy (+ optional sync/health) over one lifecycle (`open → import? → mutate → export? → recover`), serializing in-process writes through a tokio `Semaphore(1)` (D14) while reads bypass it (FR-10), with cooperative shutdown/logging (FR-17).
- **Layer:** L5 (`engine`). Acyclic invariant: `model|error → policy → storage → sync|health → config → engine → render → mcp|cli` (NFR-15).
- **Depends-on (PRD §8.1, exactly):** `unblock-config` (L4 — builds the `WorkspaceContext` incl. the `Arc<dyn Storage>` the engine consumes, CF-D), `unblock-sync` (L3), `unblock-storage` (L2 — used only via the `Storage` trait handed in through the context), `unblock-policy` (L1), `unblock-health` (L3), plus `unblock-model` + `unblock-error` (L0 — source of the relocated report/diagnostic/filter contract types, CF-A/CF-B/CF-C). External: `tokio` (`sync::Semaphore`), `async-trait` (consumed via `Storage`), `chrono`, `snafu`, `tracing`, `serde`/`schemars` (only for the report/outcome types that flow to L7). *(**No** `signal-hook`: OS signal-handler install lives in `unblock-cli` (L7) — OQ-4 RESOLVED; the engine only reads the cooperative shutdown flag.)* **No** libsql/backend type ever crosses this boundary (CF rule 2); **no** git crate / `Command::new("git")` (NFR-6).
- **Consumers:** `unblock-mcp` (L7) and `unblock-cli` (L7) are thin adapters; both call only the `Session` surface so behaviour cannot drift (FR-9, conformance rule 4).

## Public API summary (what L7 imports), per version

**v1** — `Session`; `SessionConfig`; the read methods (`get/list/ready/blocked/search/count/stale/list_dependencies/dependency_tree/detect_cycles/diagnostics` — `detect_cycles(blocking_only)`, D19; `list_dependencies`, D1); the mutation methods (`create/create_issue/create_bulk/update/delete/restore/claim/defer/undefer/add_dep/remove_dep/close_with_suggestions` — `create_issue(NewIssue)` is the MINTING single-create path, D21/T1.8; **`create_bulk(Vec<NewIssue>)` is the ATOMIC bulk MINTING create path, D22/T2.3** — one write permit + one storage tx, all-or-nothing; `create(&Issue)` is the id-preserving import/internal path); the engine-owned input `NewIssue` (D21; the `design`/`acceptance_criteria`/`assignee`/`agent_context` markdown-captured fields ADDED at T2.3/D22); the dependency-graph read (`dependency_graph`); interchange (`export_jsonl/import_jsonl/import_bd`); the lifecycle ops `doctor`/`recover` and `shutdown` (OQ-2 RESOLVED — `doctor`/`recover` are public, spine §4.1); engine-owned `ImportOptions`; `EngineError` (+ `code()`); the `is_shutdown_requested` shutdown-flag surface (the `install_shutdown` handler-install API relocates to `unblock-cli`, OQ-4); `init_tracing`. The outcome/report/diagnostic types (`CloseOutcome`, `ImportReport`, `ExportReport`, `DiagnosticKind`, `DiagnosticReport`, `DiagnosticFinding`) are **re-exported from `unblock-model` (spine §1.10)** (CF-A/CF-B — relocated so `unblock-render` (model+error only) can format them); the engine does not define them locally. `DiagnosticFinding` travels inside `DiagnosticReport`, so the engine re-exports it explicitly (G-10) so consumers importing it via engine resolve from one place. Re-exports of the contract types L7 needs — also model-owned (CF-A/CF-C) — (`ListFilters`, `CountGroupBy`/`CountBucket`, `DepTree`/`GraphEdge`, `Dependency` — backs the `dep list` action's `Vec<Dependency>`, D1) plus storage-owned (`IssuePatch`, `DeletePlan`/`DeleteMode`) so adapters import them from one place.

**v1.1** — additive: `add_comment`/`list_comments`, `rename_label`/`list_all_labels`, `epic_status`; `scheduler`/`coordination_status` (delegating to `unblock-policy` contracts); workflow-gate enforcement inside mutating transitions (`gate_check`); saved-query resolve/run; audit flight-recorder hook (`interactions.jsonl`) wired through mutate; full health taxonomy report surface. All gated behind additive `contract_version` bumps (no breaking changes to v1 signatures).

**v1.2** — additive: write-topology under libsql remote/replica sync (D14 follow-up); sync-state surfaced in `DiagnosticReport`/health; engine resolves remote credentials via config (env/keychain, never `config.toml`).

**v1.3** — additive: claim TTL/heartbeat + active-coordination orchestration; compaction/archival orchestration; tracing perf spans for the scale gate.

### T1.2 buildable scope (what THIS task lands vs what is a typed seam) — NORMATIVE

The whole v1 **public surface** above lands at T1.2 (so L7 binds to a stable API), but a few method groups have **typed not-wired seams** because their dependency crates are still stubs. Pinned split:

**BUILD now (T1.2 lands real bodies):**
- **Write-permit core** — `Arc<tokio::sync::Semaphore>` (1 permit) + `WriteGuard` RAII + `acquire_write` (shutdown-aware), D14/spine §4.2 (`src/permit.rs`, `src/session/mod.rs`).
- **All reads** (`get/list/ready/blocked/search/count/stale/list_dependencies/dependency_tree/dependency_graph/detect_cycles/diagnostics`) — delegate to `Storage`, **no write permit** (FR-10); `detect_cycles(blocking_only)` forwards the D19 filter, `list_dependencies` (D1) is the read backing the dep `list` action; `ready()` re-ranks via the `unblock_policy::cmp_ready` **free fn** (no policy handle, OQ-1). **`diagnostics(kind: DiagnosticKind)` is the 7-kind read path and STAYS BUILD-now** — it returns `DiagnosticReport { kind: <the requested kind>, findings }`, where the `kind` is the **input** (one of the seven constructible variants `Stats|Info|Where|Version|Lint|Changelog|Orphans`), never a `<integrity>` placeholder, so it has no placeholder problem (contrast `doctor()`/`recover()` below).
- **All mutations** (`create/create_issue/create_bulk/update/delete/restore/claim/defer/undefer/add_dep/remove_dep/close_with_suggestions`) — each under the single permit; `close_with_suggestions` → `CloseOutcome` (FR-11). **`create_issue(NewIssue)` (the MINTING single-create path, D21 — added at T1.8)** mints the id under the permit (root `ub-<hash>` / slug `ub-<slug>-<hash>` / hierarchical `parent.N`), probes existence via `storage.get_issue(id).await?.is_some()` (there is no `Storage::exists`), resolves `deps` into edges, and returns the created `Issue`. **`create_bulk(Vec<NewIssue>)` (the ATOMIC bulk MINTING create path, D22 — added at T2.3)** acquires the permit ONCE for the whole batch, mints every id under it (the `get_issue` probe consulting committed state AND the in-batch already-minted set — intra-batch dedup), resolves the 2-phase intra-file deps/parent IN MEMORY, builds + validates the N `Issue`s, and inserts them in the ONE `storage.create_issues(&issues, actor)` tx — rollback-on-any-failure → ZERO writes; it is NOT a loop over `create_issue`. **`create(&Issue)` (caller-supplied id, import/internal — FR-26) STAYS** and never mints. *(The single minting path is BUILD-at-T1.8; the bulk minting path is BUILD-at-T2.3; listed here so the mutation surface is complete.)*
- **`Session::open(ctx: WorkspaceContext, cfg: SessionConfig)`** — consumes the now-real `WorkspaceContext` (CF-D; storage built by config). `SessionConfig` = the spine bool struct.
- **`EngineError`** — 3 sources (`StorageError`/`PolicyError`/`ModelError`) + engine-local variants (incl. `FeatureNotWired`); `CodedError` impl.
- **`shutdown()`** flag-read + `is_shutdown_requested` (flag installed by cli, OQ-4) + `init_tracing` (`unblock.reliability` target).
- **Model-DTO re-exports** (the full spine §1.10 + storage-owned contract set).
- **Tests over REAL libsql storage** (no `Storage` mock): FR-9 interleaved-mutation **linearizability** (proptest) + dual-callsite identity; FR-10 read-during-write; D14 single-permit + cancel-safety (drop-mid-tx). A `#[cfg(test)]` `Session` ctor over `LibsqlStorage::open_in_memory` **or** via `unblock_config::open_with_storage` on a tempdir workspace (both landed) — the test harness owns workspace construction (the engine never builds storage in prod).

**SEAM-DEFERRED (T1.2 lands the SIGNATURE only; body returns `FeatureNotWired` until the dep crate lands):**
- `export_jsonl` / `import_jsonl` / `import_bd` + `open(import_on_open=true)` → the **`sync`** seam (`unblock-sync`, **T2.4**), gated behind the default-on `sync` feature.
- **`doctor()` and `recover()`** → the **`health`** seam (`unblock-health`, **T3.3**), gated behind the default-on `health` feature. Their public **signatures land in T1.2** returning `Result<DiagnosticReport>` (spine §4.1, unchanged), but the v1 **bodies return `EngineError::FeatureNotWired { feature: "health" }`** until T3.3 fills them. Rationale: the integrity report needs a `DiagnosticKind` to populate `DiagnosticReport.kind`, but no constructible variant of the landed `DiagnosticKind` (the seven above — `crates/unblock-model/src/results.rs:76-91`, mirroring FR-15 / spine §5.2) represents an integrity/doctor report. The integrity-report `DiagnosticKind` (e.g. a future `Integrity`/`Doctor` variant) **and** the `DoctorReport`→`DiagnosticReport` mapping are designed at **T3.3** with the full health taxonomy — its rightful owner — **not now**. **No model change at T1.2** (OQ-2). (Distinguish from the read-path `diagnostics(kind)`, which is BUILD-now precisely because its kind is a caller-supplied input.)

Both seams return a **typed** `EngineError::FeatureNotWired { feature }` — **never a faked success, never inline JSONL/health logic in the engine** (that would breach the L3 boundary + FR-9 single-path). They become real **additively** (no v1 signature change) at T2.4 / T3.3.

## Open questions specific to this crate

0. **Workspace-open ownership.** *(RESOLVED — CF-D, spine §4 intro + §4.1.)* `unblock-config` owns `.unblock/` discovery, opens/migrates libsql, and **builds the `Arc<dyn Storage>`**, exposing `WorkspaceContext { storage, workspace_dir, actor, config }`. The engine **consumes** the context — `Session::open(ctx: WorkspaceContext, cfg: SessionConfig)` — and never constructs storage or runs migrations itself. This keeps the acyclic layering intact (engine sees storage only through the trait object) and removes the prior ambiguity over who opens the DB.

1. **Policy handle shape.** *(RESOLVED — OQ-1, with Miguel.)* **There is NO policy handle in v1.** `unblock-policy` ships only **free functions** (`cmp_ready`/`ready_sort_key`/`is_ready`/`is_blocked`/`cache_key_*`/`filters_fingerprint`, T1.1 landed — there is no policy struct or trait-object to hold). The `Session` struct therefore has **no `policy` field**. The "no policy field" decision covers the **whole** policy-consuming surface — read **and** mutation — not just `ready()`: `ready()` calls `unblock_policy::cmp_ready` **directly** (a free-function call on the read path — zero vtable cost), and `close_with_suggestions()` likewise consumes policy as **free functions** — `is_blocked`/`is_ready` over a caller-built `ReadyContext` (`crates/unblock-policy/src/ready.rs:259`/`:317`) to compute the newly-unblocked set — so it too needs **no held policy**. The `dyn`-pluggable-policy seam (a second policy impl) is reserved for **v2** and is **additive** (it would add a field then; it does not exist now). This both removes the hot-path vtable concern and matches the landed L1 surface (free-fn-only).
2. **`recover()`/`doctor()` visibility + return type in v1.** *(RESOLVED — OQ-2, spine §4.1; seam refined at the design-Review gate, with Miguel.)* The cli `doctor` command (L7) needs a public entrypoint, so v1 exposes **both** `pub async fn doctor(&self) -> Result<DiagnosticReport>` and `pub async fn recover(&self) -> Result<DiagnosticReport>` on the public lifecycle surface. **Both return `DiagnosticReport`** (spine §4.1, verbatim) — there is **NO `RecoveryReport`** type (it is defined in no crate and not in model §1.10; the earlier sketch invented it). **v1 = seamed to `health` (T3.3), NOT v1-lite-now:** the public signatures land in T1.2 but the v1 bodies are gated behind the default-on `health` feature and return `EngineError::FeatureNotWired { feature: "health" }` until `unblock-health` lands. 3. **Import-on-open vs explicit import.** *(RESOLVED — spine §4.1.)* `SessionConfig::import_on_open` is a **`bool`** (verbatim spine §4.1) — the dogfood FR-26 convenience flag: when `true`, `open()` runs the import seam over `ctx.paths.jsonl_path` (avoiding a window where the store is empty), rather than a two-step open+import.
