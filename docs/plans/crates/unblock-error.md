# unblock-error — File-level Plan

- **Status:** PLAN (per-crate, conforms to `docs/plans/01-design-spine.md` §2 and `docs/plans/00-roadmap.md`). Any API drift requires amending the spine first (spine §6.1).
- **Date:** 2026-06-19
- **One-line purpose:** Own the **shared boundary error vocabulary** — `ErrorCode`, the 0–8 exit-code table, the structured JSON error payload (`StructuredError`), retryability/hint contract, and terminal-sanitization of human-readable messages. Backend-agnostic; no domain logic, no I/O.
- **Layer:** **L0** (`model | error`), alongside `unblock-model`. Pure leaf.
- **Depends on:** **nothing internal.** External only: `serde`, `serde_json`, `schemars`, `snafu` (for the per-crate error *pattern macros / re-exports*, see Open Question OQ-1). MUST NOT depend on `unblock-model` (would create an L0↔L0 cycle; spine §2 places `model` and `error` as independent siblings — `unblock-model`'s `Display`/`FromStr` return `unblock_error::ModelError`, so the dependency arrow is **model → error**, never the reverse).

> **Acyclicity invariant (NFR-15, spine layering):** every other library crate (`model`, `policy`, `storage`, `sync`, `health`, `config`, `engine`, `render`) defines its **own** `#[derive(Snafu)]` enum and depends on `unblock-error` for `ErrorCode` + `StructuredError`. `unblock-error` is the deepest leaf and imports none of them. The per-crate enums live in their *own* crates (D4 "no god-enum"); this crate owns only the shared vocabulary they all map *into*.

## Public API summary (what other crates import) — per version

### v1 (LOCKED — M0)
- `ErrorCode` (enum, 36 variants per spine §2.2 / §2.3 — **7 Database** (incl. `RateLimited`, T3.5/D34) + 6 Issue/operational + 6 Validation/policy + 5 Dependency + 6 Sync + 3 Config + 2 I/O + 1 Internal = 36) with `as_str() -> &'static str`, `exit_code() -> u8`, `is_retryable() -> bool`, `hint_shape() -> HintShape`, `static_hint() -> Option<&'static str>` (all `const fn`; the last two at T2.6/D25).
- `HintShape` (enum: `None | StaticText | ContextualText | SimilarIds`, serde snake_case — `"none"/"static_text"/"contextual_text"/"similar_ids"` — derives incl. `JsonSchema`; + `const fn as_str`) + two additional `const fn` views on `ErrorCode` (T2.6/D25 — the FORK-4 static hint-shape source): `hint_shape() -> HintShape` and `static_hint() -> Option<&'static str>`. **Honest per-code map (grounded in the real producer survey, never aspirational):** `StaticText` = exactly {`InvalidStatus` → `VALID_STATUS_HINT`, `InvalidType` → `VALID_TYPE_HINT`, `InvalidPriority` → `PRIORITY_DETAIL_HINT`} (the three `ModelError` fixed hints); `ContextualText` = exactly {`ValidationFailed`} (site-specific mcp quota/bulk-markdown hints; the model aggregate carries none); `SimilarIds` = exactly {`IssueNotFound`} (the T2.6 similar-ids resource fold — the tool `show` path carries no hint; presence stays per-instance, the shape describes the hint WHEN present); the remaining 31 codes = `None` (incl. `RateLimited`, T3.5/D34 — retryable carries the signal, no hint payload). The `hint_shape() == StaticText ⟺ static_hint().is_some()` invariant holds by construction (`ModelError::hint` delegates to `static_hint`). Consumed by `unblock-mcp`'s `ErrorCodeDescriptor.hint_shape` (spine §5.4 — the type is defined ONCE here). `PRIORITY_SHORT_HINT` remains exported but has no producer, so it affects no code's shape.
- `StructuredError` (struct: `code`, `message`, `hint`, `retryable`, `context`) with `from_code(code, message)`, `exit_code()`, plus context/hint builders.
- `ExitCode` newtype (`u8`, 0..=8) + `EXIT_SUCCESS`/`EXIT_INTERNAL` consts, for the CLI boundary (`process::exit`).
- `ModelError` — the one **concrete** per-crate enum that `unblock-model` returns (spine §1.1/§1.2: `Status::FromStr`, `Priority::FromStr`, `IssueValidator::validate` all return `unblock_error::ModelError`). It lives here (not in `unblock-model`) so `model` need not depend on a sibling for its own error type while still mapping to `ErrorCode`. Implements `code() -> ErrorCode`.
- `CodedError` trait — the uniform `fn code(&self) -> ErrorCode` (+ `hint`/`retryable` default views) that *every* per-crate enum implements so the L7 boundary can build a `StructuredError` from any composed error (spine §2.1 last paragraph).
- `sanitize_message(&str) -> Cow<str>` — terminal-control sanitization for the `message` field (spine §2.4 "terminal-sanitized"; NFR-14).
- `FieldError { field, reason }` — the per-field carrier inside `ModelError::ValidationFailed` (D-E1).
- Hint helpers: `find_similar_ids`, `levenshtein_distance`, `detect_status_intent`/`detect_type_intent`/`detect_priority_intent` (D-Hints) — the agent self-correction surface.
- **No macro re-export.** `snafu` is a **direct** dependency of every crate via `workspace.dependencies` (single pinned version); `unblock-error` does **not** re-export a snafu prelude or derive (OQ-1 resolved). This crate owns only `ErrorCode`/`StructuredError`/`ExitCode`/`CodedError`/`ModelError`/`FieldError`/`sanitize_message` + the hint helpers (plus `RELIABILITY_TARGET`, below).
- **`RELIABILITY_TARGET: &str = "unblock.reliability"`** (`pub const`) — the single NFR-13 tracing-target name, hoisted HERE (L0) at T3.4/D30 so `unblock-sync` (L3), `unblock-engine` (L5, which re-exports it) and `unblock-cli` (L7) all reference ONE const: `init_tracing`'s `EnvFilter` directive and every guard emit-target then cannot diverge (the by-value-duplicate silent-drop hazard — filter-target ≠ emit-target — is removed). A zero-dep string const with no domain logic; the deepest-leaf home keeps every downward edge layering-clean.

### v1.1 (LOCKED)
- No new `ErrorCode` variants are *required* by v1.1 FRs at the shared layer (FR-6/18/19/21/22 errors are expressed via the existing `PolicyViolation`, `ValidationFailed`, `RequiredField`, `NothingToDo`, `IssueNotFound`). *(**Still TRUE for the D37 comment surface pulled into v1:** the existence/row-missing guard reuses `ErrorCode::IssueNotFound` (exit 3) and body validation reuses `ValidationFailed` (exit 4) — FORK-E1 mints NO `CommentNotFound`, so the exit-code table + `capabilities().error_codes` + the shared `oneOf` are UNTOUCHED.)* **Gate codes** (FR-19 `ci_green`/`min_reviewers`/`security_sign_off`) map to `PolicyViolation` with structured `context`, not new top-level codes — keeps the golden exit-code snapshot stable. Additive `context` keys + new **hint detectors** only. (See roadmap §9: `unblock-error` `●` in v1.1 = additive.)

### v1.2 (PROPOSED — only "if a sync-state error variant is needed", roadmap §3)
- Possible additive `ErrorCode` variants for the remote/replica path: `ReplicaLagExceeded`, `SyncAuthFailed`, `RemoteUnavailable` (all exit **6** = Sync/JSONL, keeping the table's category, or exit **2** if treated as DB — decided in v1.2 design, OQ-3). All would be **retryable**. New variants are additive (no renumber) so the golden snapshot only *grows*.

### v1.4 (PROPOSED — roadmap §5)
- Possible additive variant for claim-TTL/heartbeat reclaim (FR-18 extension): `ClaimExpired` (exit 3, retryable) and `CompactionConflict` (exit 6) for archival (D12). Additive only.

## Open questions specific to this crate

- **OQ-1 (snafu re-export surface) — RESOLVED.** Each crate depends on `snafu` **directly** via `workspace.dependencies` (single pinned version, 0.8); `unblock-error` does **NOT** re-export a snafu prelude / derive macro (no fragile macro re-export). `unblock-error` owns only `ErrorCode`/`StructuredError`/`ExitCode`/`CodedError`/`ModelError`/`FieldError`/`sanitize_message` + the hint helpers. Per-crate enums each `#[derive(snafu::Snafu)]` against their own `snafu` dep.
- **OQ-2 (`context` type) — RESOLVED.** `context` is `serde_json::Map<String, Value>` per spine §2.4 (free-form object in `JsonSchema`, acceptable for FR-12 discovery). The aggregate validation detail surfaces as `context["fields"]` (D-E1, spine §2.4 mapping).
- **OQ-3 (v1.2 remote variants’ category):** When `remote` lands (roadmap §3), do `ReplicaLagExceeded`/`SyncAuthFailed`/`RemoteUnavailable` map to exit **6** (Sync) or exit **2** (Database)? Decide in v1.2 design; default proposal = **6** (they are sync-path, not local-DB, failures). Either way additive — never renumber existing codes (FR-11 stability).
- **OQ-4 (`ExitCode` type) — RESOLVED.** `exit_code() -> u8` per spine §2.2 (0..=8 fits a `u8`); the CLI casts to the platform `i32`/`std::process::ExitCode` at the L7 boundary only.
- **OQ-5 (`ModelError` home) — RESOLVED (D-E1).** `ModelError` (incl. the `ValidationFailed { fields }` aggregate and `FieldError`) lives in `unblock-error`, keeping the `model → error` arrow one-directional (spine §1.1/§1.2/§1.9: `FromStr`/`validate` `Err = unblock_error::ModelError`). `unblock-model` imports its own error enum from here; the validation hint strings stay co-located with the hint helpers.
