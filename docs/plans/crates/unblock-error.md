# unblock-error — File-level Plan

- **Status:** PLAN (per-crate, conforms to `docs/plans/01-design-spine.md` §2 and `docs/plans/00-roadmap.md`). Any API drift requires amending the spine first (spine §6.1).
- **Date:** 2026-06-19
- **One-line purpose:** Own the **shared boundary error vocabulary** — `ErrorCode`, the 0–8 exit-code table, the structured JSON error payload (`StructuredError`), retryability/hint contract, and terminal-sanitization of human-readable messages. Backend-agnostic; no domain logic, no I/O.
- **Layer:** **L0** (`model | error`), alongside `unblock-model`. Pure leaf.
- **Depends on:** **nothing internal.** External only: `serde`, `serde_json`, `schemars`, `snafu` (for the per-crate error *pattern macros / re-exports*, see Open Question OQ-1). MUST NOT depend on `unblock-model` (would create an L0↔L0 cycle; spine §2 places `model` and `error` as independent siblings — `unblock-model`'s `Display`/`FromStr` return `unblock_error::ModelError`, so the dependency arrow is **model → error**, never the reverse).

> **Acyclicity invariant (NFR-15, spine layering):** every other library crate (`model`, `policy`, `storage`, `sync`, `health`, `config`, `engine`, `render`) defines its **own** `#[derive(Snafu)]` enum and depends on `unblock-error` for `ErrorCode` + `StructuredError`. `unblock-error` is the deepest leaf and imports none of them. The per-crate enums live in their *own* crates (D4 "no god-enum"); this crate owns only the shared vocabulary they all map *into*.

## Public API summary (what other crates import) — per version

### v1 (LOCKED — M0)
- `ErrorCode` (enum, 30 variants per spine §2.2 / §2.3) with `as_str() -> &'static str`, `exit_code() -> u8`, `is_retryable() -> bool` (all `const fn`).
- `StructuredError` (struct: `code`, `message`, `hint`, `retryable`, `context`) with `from_code(code, message)`, `exit_code()`, plus context/hint builders.
- `ExitCode` newtype (`u8`, 0..=8) + `EXIT_SUCCESS`/`EXIT_INTERNAL` consts, for the CLI boundary (`process::exit`).
- `ModelError` — the one **concrete** per-crate enum that `unblock-model` returns (spine §1.1/§1.2: `Status::FromStr`, `Priority::FromStr`, `IssueValidator::validate` all return `unblock_error::ModelError`). It lives here (not in `unblock-model`) so `model` need not depend on a sibling for its own error type while still mapping to `ErrorCode`. Implements `code() -> ErrorCode`.
- `CodedError` trait — the uniform `fn code(&self) -> ErrorCode` (+ `hint`/`retryable` default views) that *every* per-crate enum implements so the L7 boundary can build a `StructuredError` from any composed error (spine §2.1 last paragraph).
- `sanitize_message(&str) -> Cow<str>` — terminal-control sanitization for the `message` field (spine §2.4 "terminal-sanitized"; NFR-14).
- Macro/helper re-exports for the per-crate snafu pattern (OQ-1).

### v1.1 (LOCKED)
- No new `ErrorCode` variants are *required* by v1.1 FRs at the shared layer (FR-6/18/19/21/22 errors are expressed via the existing `PolicyViolation`, `ValidationFailed`, `RequiredField`, `NothingToDo`, `IssueNotFound`). **Gate codes** (FR-19 `ci_green`/`min_reviewers`/`security_sign_off`) map to `PolicyViolation` with structured `context`, not new top-level codes — keeps the golden exit-code snapshot stable. Additive `context` keys + new **hint detectors** only. (See roadmap §7: `unblock-error` `●` in v1.1 = additive.)

### v1.2 (PROPOSED — only "if a sync-state error variant is needed", roadmap §3)
- Possible additive `ErrorCode` variants for the remote/replica path: `ReplicaLagExceeded`, `SyncAuthFailed`, `RemoteUnavailable` (all exit **6** = Sync/JSONL, keeping the table's category, or exit **2** if treated as DB — decided in v1.2 design, OQ-3). All would be **retryable**. New variants are additive (no renumber) so the golden snapshot only *grows*.

### v1.3 (PROPOSED — roadmap §4)
- Possible additive variant for claim-TTL/heartbeat reclaim (FR-18 extension): `ClaimExpired` (exit 3, retryable) and `CompactionConflict` (exit 6) for archival (D12). Additive only.

## Crate-level test & bench plan

- **Golden / contract suite (NFR-16, FR-11):** `tests/exit_code_table.rs` + `tests/json_contract.rs` are the *normative* pins. The 0–8 table and the serialized `StructuredError` shape are insta-snapshotted; the CI insta gate (NFR-14) makes any unintentional change fail. Adding a variant (v1.2/v1.3) is a deliberate snapshot re-bless — this is the mechanism that ties `contract_version` bumps (FR-12) to error-surface changes.
- **proptest (NFR-16):** totality/in-range of `exit_code()`; `StructuredError` JSON round-trip; `sanitize_message` invariants (no raw control bytes, idempotent, UTF-8); Levenshtein metric laws.
- **fuzz (NFR-16):** `fuzz_sanitize` over the untrusted message text path.
- **doctests:** the `lib.rs` worked example + each public constructor carries a runnable example (NFR-9 missing_docs warn forces docs).
- **MIRI:** all unit tests run clean under MIRI (no UB possible — `forbid(unsafe_code)` — but run as a cheap correctness/UB sweep per project checklist).
- **criterion (informational only):** `benches/error_path.rs`; not wired to the 10% regression gate (error path isn’t in the NFR-1 budget table).

## Open questions specific to this crate

- **OQ-1 (snafu re-export surface):** Does `unblock-error` re-export the `snafu` pattern (e.g. a thin prelude / a derive re-export) so the 8 per-crate enums share one snafu version, or does each crate depend on `snafu` directly? **Recommendation:** each crate depends on `snafu` via `workspace.dependencies` (single version) and `unblock-error` only owns `ErrorCode`/`StructuredError`/`CodedError`/`ModelError` — avoids a fragile macro re-export. Confirm before M0 codegen.
- **OQ-2 (`context` type):** Spine §2.4 types `context` as `serde_json::Map<String, Value>`. Confirm this over a typed/opaque alternative — it keeps the payload schemars-describable but `JsonSchema` for `serde_json::Value` is a free-form object (acceptable for FR-12 discovery? assume yes).
- **OQ-3 (v1.2 remote variants’ category):** When `remote` lands (roadmap §3), do `ReplicaLagExceeded`/`SyncAuthFailed`/`RemoteUnavailable` map to exit **6** (Sync) or exit **2** (Database)? Decide in v1.2 design; default proposal = **6** (they are sync-path, not local-DB, failures). Either way additive — never renumber existing codes (FR-11 stability).
- **OQ-4 (`ExitCode` type):** Spine §2.2 declares `exit_code() -> u8`; the original used `i32`. Confirm `u8` (0..=8 fits) and that the CLI casts to the platform `i32`/`ExitCode` at the L7 boundary only.
- **OQ-5 (`ModelError` home):** This plan places `ModelError` in `unblock-error` to keep the `model → error` arrow one-directional (spine §1.1 says `FromStr` `Err = unblock_error::ModelError`). Confirm `unblock-model` is content to import its own error enum from `unblock-error` rather than define it locally and depend on `unblock-error` for `ErrorCode` mapping (functionally equivalent; this choice keeps the validation hint strings co-located with the hint helpers). If reversed, `model.rs` moves to `unblock-model` and `unblock-error` keeps only the `CodedError` trait + `ErrorCode` mapping doc — amend spine §2 accordingly.
