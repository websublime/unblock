## 1. Purpose / Layer / Depends-on

**One-line purpose:** Resolve layered TOML configuration, discover the `.unblock/` workspace, **open/migrate libsql and build the `Arc<dyn Storage>`**, and expose the storage-bearing `WorkspaceContext` the engine consumes (CF-D: config owns workspace-open; engine consumes the context, it does not construct storage). A separate resolve-only `ResolvedContext` (no storage) is returned by the no-DB facade for `init`/no-workspace paths (spine §4, G-5 option b).

> **Type ownership (spine §4, NORMATIVE):** `WorkspaceContext` and `ResolvedContext` are **DEFINED in `unblock-config`** (G-9a). `WorkspaceContext` is **storage-bearing** with `storage: Arc<dyn Storage>` **NON-OPTIONAL** (spine §4.1, G-5 option b); `Session::open` consumes it and never unwraps an `Option`. The resolve-only path returns `ResolvedContext` (no storage handle).

**Layer:** L4 (`config`). Acyclic position per spine §0: `… → L3 sync | health → L4 config → L5 engine → …`. Nothing below L4 may import this crate.

**Depends-on (PRD §8.1, exact):** `unblock-storage`, `unblock-sync`, `unblock-health`, `unblock-model`, `unblock-error`. `unblock-model` is a **DIRECT** dependency: config is a value-producer that re-exports the domain knob type `unblock_model::OutputFormat` (G-7/CF-J — single home in the model) inside `ResolvedConfig`, so it imports the model directly rather than transitively. The edge is L0→L4 (a strict forward edge, acyclic — `unblock-model` is the deepest domain leaf below config). **MUST NOT** depend on `unblock-engine`, `unblock-render`, `unblock-mcp`, `unblock-cli`, or `unblock-policy` (policy is composed at L5 by the engine, not at L4 — CF-11). The layering back-edge CI check (plan §1) fails on violation.

> **Acyclicity note:** the spine lists L3 `health` as depending on `sync` and L4 `config` as depending on `storage + sync + health + model + error` (the `model` edge is L0→L4, the direct `OutputFormat` re-export). That is a strict forward edge set; `unblock-config` introduces no back-edge. The crate does **not** open the engine — it discovers `.unblock/`, builds the `Arc<dyn Storage>` (spine §4 intro + §4.1, CF-D), and returns a fully-resolved storage-bearing `WorkspaceContext { storage: Arc<dyn Storage> /* NON-OPTIONAL */, workspace_dir, actor, config: ResolvedConfig, paths: ConfigPaths }` that the engine (L5) consumes via `Session::open(ctx, cfg)` to turn into a `Session`. The resolve-only facade instead returns a `ResolvedContext` (config + paths, no storage) for `init`/no-DB paths.

> **v1 build split — T1.3a (minimal) lands BEFORE T1.2; T1.3 (full) is additive (spine §4 intro, NORMATIVE).**

## 2. Public API summary (what other crates import), per version

### v1 (subset — FR-13 subset; split across T1.3a minimal + T1.3 full — see the build-split note above)

**[T1.3a — minimal subset]** the public surface the engine consumes (facades take `start: &Path`):
- `ResolvedConfig` — the resolved, validated config VALUES the engine/`Session` reads (config-owned, spine §4 CF-D); minimal v1 shape pinned in the build-split note (NOT paths, NOT actor). DEFAULTED at T1.3a, resolved at T1.3. **`id_prefix` (default `"ub"`) is an ADDITIVE field landed by the T1.8 Implement** (D21) — the engine id-allocator reads it at mint time; additive over T1.3 (a new field with a default, no public-type break).
- `ConfigPaths` — the resolved `.unblock/` + db/jsonl paths (config-owned, spine §4 CF-D): `{ unblock_dir, db_path, jsonl_path }`. **Config OWNS path resolution from T1.3a** (single source of truth — derived from the discovered workspace + the `ResolvedConfig` filenames). DEFAULTED/derived at T1.3a, resolved at T1.3.
- `ResolvedContext` — the resolve-only context (no storage): `{ workspace_dir, actor, config: ResolvedConfig, paths: ConfigPaths }` (spine §4). Returned by `open_workspace` for `init`/no-DB paths (G-5 option b).
- `WorkspaceContext` — the **storage-bearing** context (CF-D): `{ storage: Arc<dyn Storage> /* NON-OPTIONAL, spine §4.1 */, workspace_dir, actor, config: ResolvedConfig, paths: ConfigPaths }`. Consumed by `Session::open`.
- `open_workspace(start: &Path) -> Result<ResolvedContext, ConfigError>` — resolve-only facade (no DB): `.unblock/` upward discovery → defaulted `ResolvedConfig` → path resolution into `ConfigPaths` → returns a `ResolvedContext` with **no storage handle** (for `init`/no-DB paths). **Does NOT open the DB.**
- `open_with_storage(start: &Path) -> Result<WorkspaceContext, ConfigError>` — the **workspace-open facade** (CF-D): discover → resolve `ConfigPaths` → **open libsql via `unblock_storage::LibsqlStorage::open_local(db_path)`, THEN migrate via `Storage::migrate()`** (two explicit calls — `open_local` does **NOT** run migrations; `DbOpenFailed` wraps `open_local`, `MigrationFailed` wraps `migrate()`) → build the `Arc<dyn Storage>` → actor resolution (T1.3a chain `UNBLOCK_ACTOR` → `$USER` → `"unblock"`; **FORK-4 prepends `--actor` (cli) and `config.toml [actor]`** at T1.3 — see §5 Q3) → returns a storage-bearing `WorkspaceContext` (spine §4.1). The engine consumes this via `Session::open(ctx, cfg)`; **config builds storage, engine never does.**
- `ConfigError` (snafu, per-crate; implements `unblock_error::CodedError`). T1.3a minimal variant set (spine §2.1): `WorkspaceNotFound → NotInitialized`; `DbOpenFailed → source.code()` (wraps `open_local`; typically `Backend → DatabaseError`); `MigrationFailed → source.code()` (wraps `migrate()`; `Migration`/`SchemaMismatch → SchemaMismatch`, `Backend → DatabaseError` — forwarded, not hardcoded); `ActorUnresolved → RequiredField`. The exit-7 config-file variants (`ConfigError`/`ConfigNotFound`/`ConfigParseError`) + I/O are added **additively at T1.3** with the layered resolver.

**[T1.3 — full layered resolver, additive over T1.3a]** (replaces the defaulting internals; **adds the `_with_cli` facade overloads** — the `&Path` facades stay, FORK-1; no public-type/spine-signature change):
- `open_workspace_with_cli(cli: &CliOverrides) -> Result<ResolvedContext, ConfigError>` / `open_with_storage_with_cli(cli: &CliOverrides) -> Result<WorkspaceContext, ConfigError>` — the **additive CLI overloads** (FORK-1 OVERLOAD model, spine §4 block item (3)). The `&Path` facades delegate to these passing `start` as the **walk-up START** parameter via `discover_unblock_dir(Some(start), &CliOverrides::default(), &ProcessEnv)` — **NOT** as `cli.dir` (MF-2; `cli.dir` is the explicit no-walk-up `--dir`/`UNBLOCK_DIR` override; the third arg is the `EnvSource` for `CLAUDE_PROJECT_DIR`/`$HOME`, D39 — internal signature only, the `&Path`/`_with_cli` public surface is unchanged).
- `WorkspaceConfig` — the merged, validated config value (startup + runtime keys); the full-resolver internal that *produces* `ResolvedConfig` (and `ConfigPaths`).
- `ConfigPaths::resolve(dir, cfg, cli)` + accessors (`policy_path`/`recovery_dir`) — the full-resolver path-resolution machinery (§3 `src/paths.rs`). **The `ConfigPaths` TYPE itself is a T1.3a public type** (see the T1.3a list above — config owns path resolution from T1.3a); T1.3 only enriches *how* it is filled (custom filenames, `--db` override) without changing the shape.
- `CliOverrides` — the typed top layer the CLI passes down (highest precedence); the additive facade input shape.
- `EnvOverrides` — parsed `UNBLOCK_*` layer (second precedence).
- `discover_unblock_dir(start: Option<&Path>, cli: &CliOverrides, env: &dyn EnvSource) -> Result<PathBuf, ConfigError>` — discovery of a dir named **`.unblock` OR `_unblock`** (FORK-2/D8 monorepo alias). **Precedence (MF-2 + D39):** **`--db` (derive) > `--dir`/`UNBLOCK_DIR` (`cli.dir`, explicit, NO walk-up) > `CLAUDE_PROJECT_DIR` (process-env ROOT probe via the injected `env`, NO walk-up; miss → fall through) > guarded cwd walk-up.** `CLAUDE_PROJECT_DIR` and `$HOME`/`%USERPROFILE%` are read via the injected `env` (`EnvSource`); the `&Path` facades pass `start` as the walk-up seed and `&ProcessEnv`. A symlinked dir is **canonicalized** (FORK-3). **The cwd walk-up is BOUNDED** (D39 guard — see `src/discovery.rs`). Internally the fn returns which tier won (`WorkspaceSource`) so `context.rs` can populate the context `source` field; the public `-> PathBuf` shape + the two `&Path`/`_with_cli` facade signatures are UNCHANGED.
- `discover_optional_unblock_dir(...) -> Result<Option<PathBuf>, ConfigError>` — for `init`/no-workspace commands.
- `WorkspaceConfig::resolve(cli, env, project_toml, defaults) -> Result<WorkspaceConfig, ConfigError>` — the precedence engine.
- `OutputFormat` (**re-exported** from `unblock-model`, not defined here — G-7/CF-J; `pub use unblock_model::OutputFormat`), `StartupKey`/`RuntimeKey` partition markers (FR-13 startup-vs-runtime).

#### T1.3 acceptance items (landing at T1.3 — carried from the T1.3a Verify gate)

These **land with the full layered resolver at T1.3** (they were deferred from the T1.3a minimal subset because the input surfaces they guard did not yet exist). The three security seams below are now scoped and **resolved by direction** (FORK-3 settles the symlink seam — 2026-06-26):

- **insta error golden:** add an `insta` golden snapshot of the `ConfigError` `(variant → code → exit)` table (`src/error.rs`) once the full T1.3 variant set lands (parse / unknown-key / invalid-value / I/O / credential paths). The L0 `unblock-error` exit-code golden (`unblock-error/tests/exit_code_table.rs`) already pins the `ErrorCode → exit` mapping for the minimal set; T1.3a asserts each variant's mapping with per-variant `code()` / `code().exit_code()` unit asserts, so a golden over the 4-variant T1.3a set would only re-pin what those asserts already cover — it becomes load-bearing when the variant set grows.
- **Seam A — actor bounding (lands T1.3):** route the resolved actor through **`unblock_model::validation::validate_actor`** (the **single-home** validator the model owns — spine §1.9; config is its v1 caller, an additive **model (L0) touch in-scope for T1.3**, the L0→L4 edge already exists). It bounds by **char count** (`chars().count()` ≤ `ACTOR_MAX_CHARS = 200`, NOT bytes) and rejects NUL + other **control chars**; a violation maps to `ConfigError::InvalidValue`. This fires now that the global-precedence actor input surfaces (`--actor` / `UNBLOCK_ACTOR` / `config.toml [actor]`, FORK-4) are wired. Empty/whitespace at any layer = **unset** (trimmed before bounding); an unbounded/NUL-bearing actor cannot reach storage until those surfaces exist — which is exactly T1.3.
- **Seam B — path injection (lands T1.3):** with `db_filename` / `jsonl_filename` now **config-resolved** (no longer locked constants), `ConfigPaths::resolve` guards against path-separator / `..` injection, **rejects ABSOLUTE filenames** (`Path::join` replaces the base on an absolute arg, so an absolute `db_filename`/`jsonl_filename` — and the `--db` path — would escape `unblock_dir`), and **confines** the resolved db/jsonl path within `unblock_dir` via a post-join `starts_with(canonical unblock_dir)` check so it cannot escape (NFR-18). (At T1.3a both filenames were locked constants, so no untrusted segment reached the join.)
- **Seam C — symlink workspace dir (RESOLVED, FORK-3, lands T1.3):** a symlinked `.unblock`/`_unblock` is **allowed but canonicalized**, and the resolved `db_path`/`jsonl_path` are **confined within the canonicalized `unblock_dir`** (NFR-18 blast-radius) — **not** rejected. `discovery` canonicalizes the discovered dir before `ConfigPaths::resolve` derives the artifact paths, so the DB cannot be opened outside the canonicalized subtree.

### v1.1 (full — FR-13 full; **PRD §4 D57**, `ub-lp9.2`, implementation-plan T4.2 — spine §4 "Layered configuration — FR-13 full (D57" is normative)
- **The order (D57 clause (1)), highest first: CLI > env (`UNBLOCK_*`) > project `.unblock/config.toml` > user `config.toml` > DB `config` table > defaults.** **[D57]** This CORRECTS the two ways this list used to state the DB layer's place ("between project-TOML and defaults" here, "below project-TOML" in the `db_layer.rs` row): the DB layer sits BELOW the user layer and ABOVE the defaults. Startup keys resolve over CLI > env > project > defaults only; each runtime key over every layer that carries it (`search_cap`: project, user, DB, defaults; `jsonl_export`: CLI, env, project, defaults — it is not a layer key, PRD §4 D57 clause (2), consumer tracked as `ub-p1h`).

- User layer (`user_config.rs`) — **[D57]** `$XDG_CONFIG_HOME/unblock/config.toml` when `XDG_CONFIG_HOME` is a non-empty ABSOLUTE path, else `<home>/.config/unblock/config.toml` (`<home>` = the first non-empty ABSOLUTE of `HOME`, `USERPROFILE`; a relative one is no home) on EVERY OS, through the injected `EnvSource`. - `ConfigReloader` — **[D57]** replaces the sketched `WorkspaceConfig::reload_runtime(&mut self, ...)`. `#[derive(Debug, Clone)]`, a PUBLIC constructor `ConfigReloader::new(cli: CliOverrides, env: EnvOverrides, os_user: Option<String>, project_file: Option<PathBuf>, user_file: Option<PathBuf>)` that reads nothing, and `Default` (= `new` over empty overrides, no `$USER`, no files), so every site that builds a `WorkspaceContext` by struct literal compiles (implementation-plan T4.2 lists them). A reload REPLACES the whole snapshot with what the captured layers resolve, so a site whose snapshot carries a non-default actor (the harnesses' `"tester"`) passes it at the `$USER` tier — `new(CliOverrides::default(), EnvOverrides::default(), Some("tester".into()), None, None)`, with the snapshot's `sources.actor = OsUser` — and keeps it across reloads while a DB `actor` row still overrides it, as in production (a CLI-tier actor would outrank the DB layer and make the actor-reload criterion unprovable); `Default` fits only a snapshot of pure defaults. `reload_runtime(&self, db_rows) -> Result<RuntimeConfig, ConfigError>` re-reads the project and user files, re-applies the CLI/env layers captured at open and re-resolves ONLY the four runtime keys (`jsonl_export` from the captured CLI/env layers and the project file only) against the given DB rows (faults returned, never raised), so the engine resolves a PROSPECTIVE row set before it commits (spine §4.1 `config_set`). - `classify_runtime_key(key)` and `canonicalize_runtime_value(key, raw)` — the validators the engine's `config` action calls before any write (only the three layer keys are accepted — `jsonl_export` → `InvalidValue` naming `ub-p1h`; `search_cap` in `1..=i64::MAX`; `actor` trimmed, empty refused, then `validate_actor`).
- `ConfigError::StartupKeyInRuntimeLayer { key, layer: ConfigSource }`, `ConfigError::UnknownKey { key }` and `ConfigError::FaultyDbConfig { faults }`, all → `CONFIG_ERROR`; `FaultyDbConfig` carries the recovery `hint()` naming, per blocking key, the exact call — `issue {"action":"config","op":"unset","key":"<key>"}` for a non-layer key, `op:"get"` then `op:"set"` (or `op:"unset"`) for a layer key (spine §2.1 `[D57]`). `pub fn decode_db_rows(rows: &[(String, String)]) -> Vec<DbConfigFault>` — the PURE, INFALLIBLE fault half of the DB decode (no file read), which the engine's `config_get`/`config_list` call on the rows they read.
- `policy_path()` accessor for `.unblock/policy.toml` (FR-19 gates; the policy *content* lives in `unblock-policy`, this crate only resolves the path + existence).
- `UNBLOCK_DIR_NAMES: [&str; 2]`, `has_unblock_dir_name(path: &Path) -> bool` and `probe_workspace_root(root: &Path) -> Option<PathBuf>` (`ub-lp9.14`) — the workspace-dir names in probe order (`.unblock`, then `_unblock`), the name check on a path's last component, and the child probe. The probe returns `root/.unblock` if it is a directory, else `root/_unblock` if it is a directory, else `None`, following symlinks and never canonicalizing. Discovery's tiers call them (spine §4 D39), and `unblock init` calls them to pick its target (spine §5b), so the two cannot disagree about which directory a root holds. The probe is a blocking stat, as the rest of discovery is.

### v1.3 (remote mode — proposed)
- `RemoteConfig` (feature `remote`): the endpoint URL, a startup-only key. **There is NO sync interval** — under D51 nothing syncs, so the key has no referent and is dropped rather than renamed.
- `CredentialSource` — resolves the remote auth token from `UNBLOCK_*` env **or** OS keychain **only**, never `config.toml` (NFR-18 hard rule, enforced by a deny-test).
- **OPEN at the v1.3 lock, stated so this plan does not assert a shape it has not got:** whether the reserved `backend` startup key (`:209`) WIDENS to select local-vs-remote, whether it coexists with the engine's `SessionConfig.remote` bool under a defined precedence, or whether the mode is derived from a remote URL's presence. D51 makes the mode select the LIBRARY, which makes this a real design call and not a naming one.
