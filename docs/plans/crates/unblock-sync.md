# unblock-sync — File-level Plan

- **Status:** DRAFT (conforms to `docs/plans/01-design-spine.md` + `docs/PRD.md` PRD APPROVED v1.1 + `docs/plans/00-roadmap.md`). APIs here MUST NOT drift from the spine; any change amends the spine first.
- **One-line purpose:** Light JSONL export/import — atomic temp+fsync+rename write, path-confinement preflight, conflict-marker + malformed-JSON rejection (zero DB writes on reject), tombstone-non-resurrection, and the one-shot best-effort `bd`→unblock import. **No git, no merge, no 3-way reconciliation** (D5/D13/NFR-6).
- **Layer:** L3 (`sync` | `health`).
- **Depends on:** `unblock-storage` (L2), `unblock-model` (L0), `unblock-error` (L0). Acyclic per spine layering `model|error → policy → storage → sync|health → config → engine → render → mcp|cli`. **No dependency** on policy/config/engine/render/mcp/cli (would be cyclic). Transitively re-exports nothing from libsql (NFR-15: no backend type crosses this boundary — sync consumes only the `Storage` trait + model types).

> **Scope discipline (D5).** This crate is *shrunk* relative to the original `temp/beads_rust-main/src/sync/` (`mod.rs` ~325k, `path.rs` ~58k, `history.rs`, `witness.rs`). We deliberately **drop**: git-merge / 3-way merge, 4-phase collision detection, distributed locks, witness/history snapshots, base-snapshot temp files, data-loss-guard heuristics (empty-db-over-nonempty refusal beyond a simple opt-in flag), and the `.manifest.json`/`metadata.json` machinery. We **keep** behaviour fidelity for: atomic write (temp in same dir → `flush` → `sync_all` → atomic rename; remove temp + leave original intact on error), path-confinement preflight, conflict-marker scan (`<<<<<<<`/`=======`/`>>>>>>>`), per-line JSONL validation before any DB mutation, and tombstone-non-resurrection.

## Public API summary (what other crates import)

The **only** consumer is `unblock-engine` (L5), via `Session::export_jsonl` / `import_jsonl` / `import_bd` (spine §4.1). The engine holds the write permit (D14) and calls these; sync itself acquires no semaphore and owns no concurrency policy.

### v1 (LOCKED) — surfaced from `lib.rs`

`confine_root` is the absolute `.unblock/` dir; the engine/config resolves it. Sync never discovers the workspace itself (that is L4 `unblock-config`'s job) — passing it in keeps sync acyclic and pure. Concretely (F-4): the engine passes `self.unblock_dir` (`Session`'s `pub(crate) unblock_dir: PathBuf` — the discovered, already-canonicalized `.unblock/` dir), NOT `workspace_dir` (its parent).

**Name-collision (RESOLVED, F-3):** `unblock_sync::ImportOptions` is DISTINCT from the engine's public `unblock_engine::ImportOptions { dry_run }` (spine §4.1). The engine call site refers to `unblock_sync::ImportOptions` FULLY-QUALIFIED (or aliased `as SyncImportOptions`) and MAPS `{dry_run}` → `{dry_run, allow_external: false, on_collision: CollisionPolicy::Skip}`. The MCP surface is NOT widened — `on_collision` stays internal (FORK-2); `Error`/`OverwriteIfNewer` are internal opt-ins with NO MCP exposure and NO `CONTRACT_VERSION` bump.

**Override-reason gate (NFR-5/D30 — FORWARD SEAM).** The reason-gate reject AND the reliability guard emissions live in the ORCHESTRATOR functions (`export_jsonl` / `import_jsonl` / `import_bd`), which hold the opts and know their operation label — NOT in the SHARED `preflight_source(path, confine_root, allow_external)` (`import.rs:136`, called by BOTH `import_jsonl` and `import_bd`, so it can neither see `external_reason` nor know the operation) and NOT in `conflict.rs` (both STAY pure — no `tracing`, no opts). Each orchestrator, at the top of its call, rejects `allow_external && external_reason.is_none()` with `SyncError::ExternalOverrideWithoutReason { path }` (mapped to the existing `ErrorCode::PathTraversal`/exit-6 — the confine-root-override family; NO new `ErrorCode`, NO spine §2.3/exit-table change); when the reason IS present, the honored-`allow_external` site emits EXACTLY ONE `reliability_guard!` INFO carrying `operation` + `path` + `result="external-path-force-override"` + `reason=<the written reason>` — a SINGLE event covering BOTH the NFR-13 "external path use" and "force overrides" categories (they COINCIDE in v1: the only external-path mechanism IS the reason-gated `allow_external`, so a separate "external-path" event AND a "force-override" event would double-fire the same call). The **operation vocabulary is pinned to exactly `"export"` / `"import"` / `"import_bd"`** (each orchestrator passes its own label). This is UNREACHABLE in v1: the engine forces `allow_external: false` (`interchange.rs:37,71`), the MCP `sync` tool does not expose it, and there is no CLI export/import command — so the **public engine `ImportOptions` stays `{ dry_run }`** (spine line 1233 unchanged) and there is **NO `CONTRACT_VERSION`/`CONTRACT_HASH` bump**. The full DB-persisted policy-bypass (`bypass_reason`, beads `close_policy.rs` parity) STAYS v1.1 (`crates/unblock-policy.md` `src/gates.rs`) — do NOT build policy gates in T3.4.

**Import apply is ATOMIC (MF-1/D23 clause (5)):** the production (default `Skip`) path is all-or-nothing — a classify-then-atomic-create shape that (1) preflights + validates (zero DB writes on any failure), (2) classifies EVERY incoming record via read-only `get_issue` probes (tombstone-guard → `sync_equals`-skip → exists-skip → collect the new-id subset), then (3) applies the new-id subset through ONE `Storage::create_issues` transaction (the T2.3 atomic primitive, rollback-on-any → zero rows). NO per-record `create_issue` loop; NO new storage trait method (`create_issues` is ALSO the import atomic-apply primitive). The classify probes and the `create_issues` tx run under the SAME engine D14 write permit; cross-process serialized by the D31 `.write.lock` (whole-mutation scope), so no concurrent writer can insert a classified-new id between probe and tx. `imported` is set only after the tx COMMITS. A dangling `depends_on_id` edge (intra-batch or against the existing DB) is ACCEPTED and committed — `dependencies.depends_on_id` has **no** foreign key (`crates/unblock-storage/src/libsql/schema.rs:14,115`), intentionally faithful to beads' `external:` refs — so it does **not** trigger the whole-batch rollback; the k-of-n atomic guarantee is exercised instead by a colliding id / backend error on record k (in-tx failure via the single `create_issues` `with_immediate_tx`). Still do NOT hand-roll edge insertion — reuse the storage path. `OverwriteIfNewer` (which needs `update`) is an INTERNAL, non-production opt-in — `#[cfg(test)]`-gated (SH-2) so no future caller trusts it — OUTSIDE the FR-8 atomic guarantee. Faithful to the original single-`with_write_transaction` import (`mod.rs:4493`).
