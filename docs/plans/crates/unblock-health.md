# unblock-health — File-level Plan

- **Status:** v1 (HEALTH-LITE, D29) SHIPPED; v1.1 (FR-16 full) SPECIFIED by **PRD §4 D58** (`ub-lp9.3`, implementation-plan T4.3). Source of truth: PRD APPROVED v1.1. Conforms to `docs/plans/01-design-spine.md` (AUTHORITATIVE interface contract — §3.1 "Health facts and repair requests", §3.2 `health_facts`/`repair`, §3.3 pre-open primitives, §4.1 `doctor`/`recover`, §5b `doctor`). **[D58] REWRITTEN 2026-11-13:** the previous draft (2026-06-19) gave the classifier a `&dyn Storage` (breaking D29 clause F3), listed bd anomaly classes whose tables do not exist, promised v1.3 sync-lag checks D51 deleted, and mapped `SidecarMismatch` to `Drifted` against D29 clause F5 and the code. The v1 rows below record what shipped; the v1.1 rows are what D58 adds or deletes.
- **One-line purpose:** classify a workspace's health — v1: libsql `integrity_check` rows + pure file-state checks; v1.1: the four levels DEFINED BY REPAIR PATH (`Drifted` = derived-state drift inside the database, `Recoverable` = an in-product repair exists, `Unsafe` = none does), the planned repairs, and the `.unblock/.recovery/` evidence layout.
- **Layer:** L3 (`sync | health`).
- **Depends-on (must match spine/PRD §8.1, acyclic):** `unblock-model`, `unblock-error`, `unblock-sync` (**[D58] the edge gets its first use: `scan_conflict_markers`**). **Forbidden:** any `unblock-storage` dependency, in v1 AND v1.1 (D29 clause F3, KEPT by D58 clause (4)); any back-edge to `config`/`engine`/`render`/`mcp`/`cli`; libsql, git, network. Health never holds a `Storage` handle, never opens the database and never sees a libsql type (NFR-15): the ENGINE gathers every fact and passes it in as DATA. The xtask layering whitelist (`xtask/src/layering.rs`) and the `ub-lp9.25` gate's PC8 row pin this.

> **D29 (v1, HEALTH-LITE) — what shipped.** Six modules (`lib`/`error`/`level`/`paths`/`file_state`/`doctor`); `run_doctor(integrity_rows, paths)` pure and non-async (F3); `Session::doctor()` wired with the lite body (F4); `recover()` left `FeatureNotWired` (F1); the F5 severity map. **D58 SUPERSEDES F5's map and F4's exit mechanism, WITHDRAWS the CF-E probe reservation, and KEEPS F3.**

> **The boundary rule (D58 clause (4)), stated once.** `classify` takes `PreOpenFacts` (std::fs reads the engine makes BEFORE the process opens any libsql connection), `Option<DbFacts>` (the engine's mapping of `Storage::health_facts()`; `None` when the database could not be opened — missing or not SQLite), `ExportFacts` (health's own `scan_export(path)`, the ONE call of `unblock_sync::scan_conflict_markers` — the declared `unblock-sync` edge's first use, called by the engine) and `AdvisoryFacts`. A v1.3 remote probe result arrives the same way, as a new input field (D58 clause (10)). The CF-E `Storage::diagnostic_probe(DiagnosticKind)` seam is WITHDRAWN: it was keyed on the published `DiagnosticKind`, so it would have moved `CONTRACT_HASH`.

## Public API summary (what other crates import)

Consumer: `unblock-engine` only (`Session::doctor`, `Session::recover`, `preopen::gather_preopen`, `preopen::repair_preopen` — spine §4.1). The cli reaches health only through the engine's `HealthReport` (it re-exports `HealthLevel` and `PlannedRepair`).

**v1.1 (D58):**
- `HealthLevel { Healthy, Drifted, Recoverable, Unsafe }` — unchanged enum and order; composite = `max`. `as_str`, `is_operable` (Healthy|Drifted), `needs_recovery` (Recoverable), `is_fatal` (Unsafe).
- `PreOpenFacts { db: DbFileFact, lost: bool, wal_len: Option<u64>, shm_present, journal_present, write_lock_held, recovery_entries: Vec<RecoveryEntry> }` with `DbFileFact { Absent, Empty, Unreadable { reason }, NotSqlite { len }, SqliteHeader }` — every field gathered by `std::fs` before any libsql connection exists in the process (D58 clauses (6)–(7), criterion (n)); `lost` is `unblock_storage::lost_database`'s answer (the file absent or 0 bytes while `.write.lock` exists), computed by the engine.
- `DbFacts { integrity_rows: Vec<String>, schema_version: i64, expected_schema_version: i64, index_names: Vec<String>, child_counter_drift: Vec<(String, u32, u32)>, duplicate_metadata_keys: Vec<(String, u32)> }` — the engine maps storage's `DbHealthFacts` into it, so no storage type crosses the boundary.
- `ExportFacts { path: Option<PathBuf>, scan: ExportScan }` with `ExportScan { Absent, Clean, ConflictMarkers { first_line: usize }, Unscannable { reason: String } }`, returned by `fn scan_export(path: Option<&Path>) -> ExportFacts`, which calls `unblock_sync::scan_conflict_markers` (its I/O, file-size and line-length guard errors become `Unscannable`). The export is never the database file, so this read is outside the `howtocorrupt.html` section 2.2 rule.
- `AdvisoryFacts { now_utc }` — the clock is injected, so the 30-day stale rule is testable.
- `AnomalyClass` — exactly the D58 clause (1) classes, in report order: `DatabaseLost`, `DatabaseUnreadable`, `DatabaseNotSqlite`, `SidecarMismatch`, `TruncatedWal`, `JournalSidecarPresent`, `JsonlConflictMarkers`, `JsonlUnscannable`, `IndexCorruption { index, row }`, `PageCorruption { row }`, `ChildCounterDrift { parent_id, stored, observed_max }`, `DuplicateMetadataKey { key, rows }`, `SchemaStampBehind { observed, expected }`, `SchemaStampAhead { observed, expected }`; each with ONE `code()` (`database_lost` … `schema_stamp_ahead`), `severity()`, `planned()` and `Display`.
- `Advisory { DatabaseNotCreated, StaleRecoveryArtifacts { count, oldest_days: Option<u32> }, WriteLockHeld }` — reported, never a severity (`DatabaseNotCreated` = no database and no `.write.lock`: a fresh clone or worktree).
- `PlannedRepair { anomaly: &'static str, action: PlannedAction, path: RepairPath }`; `PlannedAction { QuarantineDatabase, QuarantineSidecar, QuarantineJournal, CheckpointTruncate, Reindex { index }, RaiseChildCounter { parent_id, to }, DedupeMetadataKey { key }, Migrate, RegenerateExport, Manual { text: &'static str } }`; `RepairPath { PreopenExclusive, Online, Manual }`.
- `WorkspaceClassification { level, anomalies, advisories, planned }` with `is_operable`, `needs_recovery`, `recovery_possible` (= `level != Unsafe` — bd's rule, kept) and `audit_record`.
- `fn classify(pre: &PreOpenFacts, db: Option<&DbFacts>, export: &ExportFacts, adv: &AdvisoryFacts) -> WorkspaceClassification` — PURE and NON-async (criterion (m) pins it with a `const` function-pointer binding).
- `fn classify_integrity_row(row: &str, index_names: &[String]) -> AnomalyClass` — the clause (3) split.
- `recovery::{RunDir, Manifest, ManifestFile, ManifestAction, run_dir_name, scan_recovery_root}` — naming, creation and manifest I/O confined to `.unblock/.recovery/` (no database file is ever opened here).
- `ReliabilityAuditRecord` (NFR-13, target `unblock.reliability`, fields `operation/path/result/reason` — PRD wins over bd's `source/phase/outcome`).
- `HealthError { Io, IntegrityCheckFailed, Serialize, RecoveryEvidenceWrite { source, path } }` → `IoError`/`DatabaseError`/`InternalError`/`IoError`.

**Deleted at v1.1 (D58):** `FileAnomaly` (its classes fold into `AnomalyClass`), `classify_file_state`, `run_doctor`, `DoctorReport`, `HealthSummary`, `jsonl_has_conflict_markers` (one scanner — sync's) and `is_orphaned_lock_file` (`.unblock.lock` is never written, D31; replaced by `WriteLockHeld`). The v1 draft of this plan named an `unblock-fuzz` target over `jsonl_has_conflict_markers` and `classify_file_state`; it was never built (the fuzz manifest has no such `[[bin]]`), and both functions are deleted.

## Crate-level test & bench plan

- **Unit/property/golden:** as tabled. NO mock `Storage` — health has no storage dependency; the facts ARE the test seam.
- **End-to-end:** the engine and cli own them (`crates/unblock-engine/tests/health.rs`, `crates/unblock-cli/tests/migrate_doctor.rs`, implementation-plan T4.3), because only they open a database.
- **Fuzz (NFR-16):** no `unblock-fuzz` target. The crate parses no untrusted input: integrity rows come from SQLite and the export is scanned by `unblock-sync`, whose plan owns any scanner target. `classify_integrity_row` gets a proptest over arbitrary strings instead (total, never panics, unknown text → `PageCorruption`).
- **Lints/gates:** `forbid(unsafe_code)`, clippy pedantic; layering (no storage edge); no libsql/git/network crate.
