## Public API summary (what other crates import)

Consumers: `unblock-engine` (composes health; backs `Session::doctor`/`Session::recover` and `Session::diagnostics`, spine §4.1 — OQ-2 RESOLVED), transitively `unblock-cli` (`doctor` command, FR-16) and `unblock-mcp` (`diagnostics` tool, FR-15 / spine §5.2). Health never depends on engine and holds NO `Storage` handle (F3/D29 — storage-free); the engine owns storage, calls `Session::integrity_check()`, and passes the integrity rows (`Vec<String>`) + paths into `run_doctor`. The engine maps health's `DoctorReport` (v1) / `WorkspaceClassification` (v1.1) into the model `DiagnosticReport`/`DiagnosticFinding`/`DiagnosticKind` it returns from `Session::doctor`, REUSING `DiagnosticKind::Info` for the v1 lite report (F2 — no spine §1.10 change; spine §4.1).

**v1 (lite):**
- `HealthError` (snafu, per-crate; `fn code(&self) -> unblock_error::ErrorCode`).
- `DoctorReport` — aggregated v1 diagnostic result: `integrity_ok: bool`, `integrity_rows: Vec<String>`, `file_state: Vec<FileAnomaly>`, `summary: HealthSummary`. `Serialize + JsonSchema` (flows into `DiagnosticReport` at the engine/MCP boundary).
- `FileAnomaly` — v1 subset of file-state findings (db missing / not-sqlite / sidecar mismatch / truncated-wal / journal-present / orphaned-lock / jsonl-conflict-markers). `Serialize + JsonSchema`.
- `HealthSummary { integrity_ok: bool, anomaly_count: usize, worst: HealthLevel }`.
- `HealthLevel` — **v1 ships the full 4-variant enum** (`Healthy | Drifted | Recoverable | Unsafe`) so the contract is stable from day one; v1 only ever *produces* `Healthy`/`Recoverable`/`Unsafe` from the lite checks, `Drifted` becomes reachable in v1.1.
- `fn classify_file_state(db_path, jsonl_path) -> Vec<FileAnomaly>` — pure, no DB handle.
- `fn run_doctor(integrity_rows: &[String], paths: &WorkspacePaths) -> Result<DoctorReport, HealthError>` — the engine-facing entrypoint, **PURE and NON-async** (F3/D29): the engine calls `Session::integrity_check()` and passes the `Vec<String>` rows in; `run_doctor` runs `classify_file_state`, then aggregates. NO `unblock-storage` dep, NO DB handle.
- `WorkspacePaths { db: PathBuf, jsonl: Option<PathBuf>, recovery_dir: PathBuf }` — pure path bundle passed in by the engine (health does NOT discover `.unblock/`; that is config's job).

**v1.1 (full taxonomy):**
- `WorkspaceHealth = HealthLevel` (alias kept; the 4-state enum already public from v1).
- `AnomalyClass` — full enum (file-state ∪ db-state ∪ drift ∪ recovery-artifact variants), each with `.code() -> &'static str`, `.severity() -> HealthLevel`, `Display`.
- `WorkspaceClassification { health: HealthLevel, anomalies: Vec<AnomalyClass> }` with `from_anomalies` (composite severity = `max`), `is_operable`, `needs_recovery`, `recovery_possible`, `audit_record`.
- `ReliabilityAuditRecord` + `AnomalyAuditEntry` (NFR-13 `tracing` on `unblock.reliability`).
- `async fn classify_workspace(storage, paths, opts) -> Result<WorkspaceClassification, HealthError>` — the full check pipeline (file-state + db-state probes via the `[v1.1]`-additive `Storage::diagnostic_probe(kind)` / `diagnostic_probes()` seams reserved in spine §3.2 (CF-E; depended on by config db-layer + health full-taxonomy) + optional drift when JSONL export enabled).
- `RecoveryEvidence` writer — preserves pre-recovery artifacts under `.unblock/.recovery/` (FR-16 full). Health *describes* recovery; it does not mutate the live DB (engine orchestrates any repair).

**v1.2 / v1.4:** additive variants + check fns only (sync-lag/conflict in v1.2; scale diagnostics in v1.4); no shape changes to the v1.1 contract.

## Open questions specific to this crate

1. **Storage handle vs integrity rows at the boundary.** ✅ **RESOLVED (spine amendment CF-E; v1 boundary fixed by F3/D29).** For v1-lite, health is **storage-free**: it takes NO `Storage` handle at all — the engine calls `Session::integrity_check()` and passes the `Vec<String>` rows into the pure, non-async `run_doctor` (F3). Spine §3.2 gives `Storage::integrity_check() -> Result<Vec<String>, StorageError>` for v1. v1.1's db-state probes (duplicate schema rows, NULL-in-NOT-NULL, write-probe, child-count drift) need *more* than integrity rows, so the spine now reserves `[v1.1]`-additive diagnostic-probe seams on the `Storage` trait (§3.2): `diagnostic_probe(&self, kind: DiagnosticKind) -> Result<DiagnosticReport, StorageError>` and `diagnostic_probes(&self) -> Result<Vec<DiagnosticReport>, StorageError>` (taxonomy mirrored from model §1.10 / spine §5.2). v1.1's `classify_workspace` consumes these (option (a) — extend the trait, keeping backend opacity); v1 impls may return empty/`NothingToDo`. The full-taxonomy db-state probes in `src/classify.rs` `[v1.1]` therefore depend on these reserved seams, not on a new query callback.
2. **`Degraded` → `Drifted` rename + v1 severity map (OQ-2).** ✅ **RESOLVED / RATIFIED (F5/D29, Miguel 2026-07-08).** `Drifted` is the ONLY mid-tier (no separate `Degraded`), scoped to JSONL-export drift and therefore **never produced in v1-lite**. All original `Degraded` anomalies that are *not* JSONL-drift are re-homed to **`Recoverable`** (`SidecarMismatch`/`JournalSidecarPresent`/`OrphanedLockFile`), joining the byte-faithful `DatabaseMissing`/`DatabaseNotSqlite`/`TruncatedWal`→`Recoverable`; `JsonlConflictMarkers`→`Unsafe` is the only v1 `Unsafe` producer. `OrphanedLockFile` (`.unblock.lock`, D8) is ported faithfully (defensive/vestigial under the D14 in-process Semaphore, but dropping it would be a forbidden simplification). This is the v1 severity map captured in the `file_state.rs` row above.
3. **Who discovers paths?** This plan keeps health pure over a `WorkspacePaths` supplied by the engine/config (config owns `.unblock/` discovery, L4). Confirm health must never read config directly (it sits at L3, below config L4 — so it structurally cannot; the engine bridges). 
4. **Recovery execution boundary.** v1.1 `recovery.rs` only *preserves evidence* and *describes* repair; the live-DB mutation (WAL checkpoint, integrity-driven rebuild) is the engine's job (single write permit, D14). Confirm health never opens a writable DB handle.
5. **Drift requires reading JSONL via `unblock-sync`.** The only reason health depends on sync is v1.1 drift (`DbJsonl*`, `ExportHashMismatch`). Confirm the exact sync API health calls (line count / id-set / export-hash) so the dependency stays minimal and one-directional.
