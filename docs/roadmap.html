v1.3Proposed
Shared state — one primary, many machines

Where unblock becomes a team product (D28) — the release right after planning, guardrail-pinned. Sync backend chosen at lock with a fresh maturity check.

  • Turso Sync vs libsql embedded replicas — decided at lock (replicas now vendor-legacy)
  • Reads local, writes serialize at the primary · join-workspace onboarding
  • Credentials via env / OS keychain only · self-hosted sqld path
  • No multi-master — integrity first
heart storage — + config · health · engine · mcp · cli
v1.4Proposed
Human surface — local TUI

An offline, terminal-native window for developers — a ratatui app that is itself an MCP client over stdio (no new transport, FR-9 preserved). Pulled forward from v1.5.

  • Phase 1 read-only: ready queue, board, detail, swarm observability
  • Phase 2: claim/close/create via the same MCP tools, human as actor
  • Rides real planning (v1.2) + coordination (v1.1) data instead of shipping thin
  • 100% Rust — no Node/npm; dependency graphs → the PRO web
new unblock-tui (13th crate) · cli (tui command)
