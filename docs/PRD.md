> **unblock** is a ground-up, idiomatic, multi-crate Rust rewrite of the deprecated `beads_rust` tool
> (binary `br`, an "agent-first issue tracker"; source under `temp/beads_rust-main`). It is grounded in a
> code-confirmed discovery of the original (25 functional / 17 non-functional requirements, 11 domain
> entities) and reshaped by explicit, locked product decisions (§4).
>
> **Value proposition:** *unblock is the only local, offline-capable, dependency-aware issue store with
> atomic multi-agent claim, a versioned dependency-aware scheduler, and contention-safe swarm coordination
> at 250k+ issues — no accounts, no internet, with a credible shared-state path via libsql sync.*

---

## 1. Overview & Vision

unblock is a **local-first, agent-first issue tracker** purpose-built so AI coding agents — and the humans
orchestrating swarms of them — can keep **dependency-aware, machine-readable issue state next to the code**,
with no accounts and no external service required.

It inverts the original product's interface: the **Model Context Protocol (MCP) is the primary surface**.
Every domain feature is exposed as MCP tools/resources/prompts over stdio; the command-line binary exists
only for **lifecycle/operations** (mcp, migrate, doctor, version, init, agents, update — D3), not as the feature surface.

Persistence is a **libsql** (Turso SQLite fork) database — the **source of truth** — accessed behind a
`Storage` trait, local-file by default with a native path to remote/replicated sync later. A line-oriented
JSONL export/import is retained as an **optional** portability/audit feature (git-diffable snapshots), **not**
as a synchronization mechanism.

### 1.1 Competitive context

| Alternative | Why unblock instead |
|---|---|
| **GitHub MCP server** (issues as MCP tools) | Requires internet + account; no dependency graph; no atomic claim; no offline. |
| **saga-mcp** (TS, SQLite, hierarchy + deps + audit) | No atomic claim; single-agent assumption; no swarm-coordination diagnostics; no scheduler; no performance validation; TS runtime overhead. |
| **Raw SQLite MCP server** | No domain model; no exit-code/error contract; no typed dependency edges. |

**Defensible wedge:** swarm-scale correctness at 250k+ issues — atomic multi-agent claim, contention-safe
coordination, a versioned agent error contract, and a dependency-aware scheduler. Everything else is table stakes.

## 2. Problem Statement

External trackers (GitHub Issues, Jira, Linear) require internet and accounts, fragment context away from the
code, cost money, and expose weak machine APIs; bare TODO comments carry no status, dependencies, or
queryability. AI coding agents working in swarms need **deterministic, non-interactive, dependency-aware**
issue state that lives with the repo, is offline-capable, and is machine-readable end to end.

The **trust anchor** is the local libsql database (durable, transactional, with a real sync protocol for the
shared case). Issues no longer need git as a transport; a git-diffable JSONL snapshot remains available as an
**optional, secondary** convenience for audit and review, not as the source of truth.

The original `beads_rust` delivered the agent value but accreted into an unmaintainable shape: a single
~50k-LOC binary crate with by-convention-only layering, monster files (`storage/sqlite.rs` ~22.6k LOC,
`sync/mod.rs` ~9.4k, `doctor.rs`), write-orchestration logic duplicated between the CLI and the MCP server,
and a deep dependency on niche single-author sibling crates — most critically the pre-1.0 pure-Rust
**fsqlite** SQLite engine (15 crates) whose error type leaked into the public API and which **hot-spins at
100% CPU on lock contention** (defect 243), forcing `busy_timeout=0` plus a hand-rolled backoff.

unblock delivers the same agent value as a **coherent, acyclic multi-crate workspace** with an embeddable
core, a mainstream storage backend behind a trait, MCP as the first-class interface, and the agent contract
preserved.

| **D20** | **Live issue restore (un-tombstone) — net-new (no `bd` precedent).** A **dedicated** `Session::restore(id)` / `Storage::restore_issue(id, actor)` (NOT an `update` patch) reverses a SOFT delete (FR-1c "recoverable"). **(1) Target status = best-effort via `closed_at`:** restore lands `Closed` iff `closed_at.is_some()`, else `Open` — the pre-delete status is not preserved (only `original_type` survives), so `closed_at` is the only was-Closed signal; this also self-satisfies the issues-table CHECK constraint on both branches. | **D21** | **Issue-id generation scheme + atomic minting in the engine (FR-1a).** A faithful port of the classic `bd` adaptive-base36 id scheme, minted by the **engine** under the **D14 write permit**. **Prefix is CONFIG-DERIVED (default `ub`):** the issue-id prefix is **not** a hard-coded constant — it is resolved from `unblock-config` (an ADDITIVE config key, default `ub`, faithful to the original `IdConfig::with_prefix`/`issue_prefix`), normalized via the model `normalize_prefix`, and the engine allocator reads it from the `WorkspaceContext`/`ResolvedConfig` it already holds at mint time (so `ub-` in `ub-<hash>`/`ub-<slug>-<hash>` is the *default* rendering, overridable per workspace). **Creator seed:** the engine resolves the actor → `creator` and passes it as the seed's `creator` field at mint (`generate_id_seed(..., creator, ...)`, faithful to the original `IdGenerationInput.creator`). **(1) Root id = `ub-<hash>`:** SHA-256 over a length-prefixed seed (`len:title`, `len:description`, `len:creator/actor`, `len:created_at` nanos, `len:nonce`), first 8 bytes → `u64` → base36-lowercase, truncated to an **adaptive length** (`min=3..max=8`) chosen by the birthday-problem heuristic `P(collision) ≈ 1 − e^(−n²/2·36^len) < 0.25` over the current issue count; the candidate loop tries nonces `0..10` at a length, then **grows the length**, then the original's saturated fallback (12-char hash, then `…{nonce}` desperation), probing each candidate against storage via `get_issue(id).await?.is_some()` (the existence probe reuses the `get_issue` read — there is **no** `Storage::exists` method) — all **under the write permit** so the probe→insert is atomic. **(2) Slug variant `ub-<slug>-<hash>`** (optional user slug): the slug is normalized to lowercase ASCII-alphanumeric + single hyphens (cap 48 chars, trailing-hyphen-stripped) via the model's `normalize_slug`, then made **prefix-budget-aware** via `normalize_slug_for_prefix(slug, prefix)` — which fits `<prefix>-<slug>` within `MAX_ID_PREFIX_LEN` (=64), truncating the slug to the remaining budget (and re-trimming a trailing hyphen) or **dropping the slug entirely** (empty drop-signal) when the prefix alone exhausts the budget; the **hash suffix is always appended** (uniqueness); an empty-after-normalization slug (or a budget-exhausted drop) falls back to the hash-only `ub-<hash>` ladder. **(3) Hierarchical child id = `parent.N`** when a `parent` is supplied: `N` = storage's existing `next_child_number(parent)` (its `child_counters` high-water mark), then `create_issue` bumps the counter in-tx. **(4) Placement = engine, NOT L7:** the mint+probe+insert (and the child-counter read→bump) MUST be serialized under the single write permit so two concurrent creates under the same parent cannot mint the same `parent.N` — this is **why** minting cannot live in the CLI/MCP adapters; FR-9's single-mutation-home keeps MCP and CLI from drifting. The pure, deterministic candidate compute (hash/seed/adaptive-length/slug-normalize) lives in **`unblock-model`** (`id.rs`, alongside the parser); the **stateful** collision-retry loop + the storage existence probe (`get_issue(id).await?.is_some()`, NOT a `Storage::exists`) and the `next_child_number` read live in the **engine** id-allocator. **(5) `Session::create(&Issue)` (caller-supplied id) STAYS** — it is the **import/internal** path (it preserves caller ids so the `content_hash`-keyed import idempotency, FR-26, is byte-stable; it **never mints**). A **new** engine minting path (`create_issue(NewIssue)`) is added for **interactive** create (MCP/CLI), resolving `parent`→`parent.N`, adding `deps` as edges in/after the same tx, and returning the created `Issue`. **[amended by D44 (v1.0.1) — the clause text above is D21's ORIGINAL, deliberately PRESERVED: "in/after the same tx". D44 DELETES the "after" arm, so the clause now reads "in the SAME transaction as the issue row"; the original wording is kept legible here because that permissive disjunction is itself part of the record of how the defect survived GA review.]** That single transaction is now BINDING (the pre-D44 code wrote each edge in an independent follow-up transaction), and the edge SOURCE is IMPLICIT: `deps[].issue_id` is omitted and the edge binds the id this path just minted, precisely BECAUSE this clause put minting in the engine — a client cannot derive a server-minted id, so the field is removed from its burden rather than made guessable. D21's own decision (engine-side minting under the permit) is UNCHANGED. | FR-1a needs a real id to mint, and the child-counter `next_child_number`→`+1` read-modify-write is a **race** unless serialized — so minting MUST run atomically under the D14 permit (an L7 adapter cannot guarantee that), and FR-9's single mutation home keeps MCP and CLI on one path. The `bd` adaptive scheme keeps ids short while collision-safe as the DB grows; the slug variant keeps ids human-recognizable. Keeping `create(&Issue)` separate preserves the import path's id-preservation (FR-26 idempotency), which a minting path would break. Splitting pure-compute (model) from the stateful probe (engine) keeps `unblock-model` I/O-free while reusing the existing `id.rs` parser home. |
| **D22** | **Bulk-markdown import + create-surface field fidelity (FR-1a).** Two coupled decisions landing the `bd create --file` bulk-markdown feature on the MCP `issue` tool **and** closing the create-surface field gap it exposes. ### Persistence & interchange (model B)
- **FR-7 [must] — Persistence + optional JSONL interchange.** libsql is the source of truth. Provide **optional** `export`/`import` to/from a line-oriented `issues.jsonl` for portability/audit/git-diffable snapshots. Export is atomic (temp in same dir → flush + `sync_all` → atomic rename; on error remove temp, leave original intact). **No** automatic three-way merge, **no** git operations. **Since D45 the export corpus is CLOSED UNDER ITS BLOCKERS:** the D23 corpus filter drops ROWS (ephemeral / `-wisp-`) while the edges pointing AT them were still serialized, so the exporter could emit a file its own importer would refuse. D45 does NOT drop those edges — dropping one would turn a BLOCKED issue into a READY one in the destination workspace, because an issue blocked by an ephemeral row is blocked today. The corpus WIDENS instead, and the rule is over ROWS: **a row the filter excluded stops counting as excluded once it stands in a non-external dependency relation with an exported row, in EITHER direction — so a row that BLOCKS something exported is exported.** It travels transitively, to a fixed point (terminating on cycles), its `ephemeral` flag serialized verbatim; an external id pulls nothing and is pulled by nothing, being no row at all. **Following INCOMING edges too is forced, not decorative:** a `parent-child` edge is stored on the CHILD's row, and it is what makes an epic PARENT blocked, so an out-edge-only closure would export a blocked epic whose child stayed behind and hand the destination a READY epic.   real hot-spin gave R≈28 on 14 cores but R≈4.42 on a 4-vCPU runner: a generous absolute budget is MORE portable than
  a tight relative delta). The create budget applies to the **storage insert path**
  (`Storage::create`/`create_issues`); the engine-mint `Session::create_issue` recomputes `issue_count()` per create
  (O(N) at scale — a known v1.5 cached-count limit, not an NFR-1 miss).

  (writes serialized at the primary), with a read-only fast path. **v1 commits to 250k issues validated in
  CI** (ci-cd `scale` job, storage/engine; owner impl-plan T3.5): the corpus is seeded **storage-direct,

Its home is the `tests/migrations.rs` cell the storage crate plan already specified and which never existed. Two rules ride with it: the historical DDL the fixture applies is FROZEN HISTORY — the past cannot drift, so that constant must never be "updated" to track the current DDL, and it stays a SEPARATE constant even though D46's frozen-baseline discipline makes it byte-identical to the production baseline today (pointing the fixture at `SCHEMA_SQL` would couple the past to a constant someone may still legitimately touch, and would quietly turn "seed an earlier state" back into "create a fresh one") — and every claim of the form "this cell pins X" is proven by APPLYING the mutation and observing red, never by reading the test (§4, D46).
- **NFR-17 [reliability/security] (D17/D35)** Distribution/self-update via `dist`/`axoupdater` (v1): each artifact is **SHA256-checksum-verified by the dist installer** (from `dist-manifest.json`) before the swap (`self_replace`); **GitHub artifact attestations** are publish-side provenance (`actions/attest@v4`, verified out-of-band via `gh attestation verify`), NOT consulted on the auto-update path — the installer SHA256 check-before-swap is the sole client-side integrity gate; **no network calls on any normal command path** — only on explicit `unblock update` (offline-first; libsql remote behind a non-default feature, D15). See `docs/plans/ci-cd-and-distribution.md`.
- **NFR-18 [security — threat model]** The MCP tool surface is an untrusted-input boundary: every `tools/call` is **duplicate-key-scanned at the transport before parse (D43)**, then **quota-checked and strictly deserialized** at the L7 boundary — `schemars` PUBLISHES the input schema, it does **not** enforce it (there is no runtime validator in the process); the enforcement is `enforce_quota` + `#[serde(deny_unknown_fields)]` (D42). **"Per-request bytes" is DEFINED as the serialized `tools/call` `params` object** — `name` + `arguments` + `_meta` + `task`, excluding the JSON-RPC envelope, which is not reachable from `ServerHandler::call_tool` — checked ONCE, pre-dispatch, inside the rate-limit permit. **Size limits** (per-request bytes / array / string / object-KEY / batch caps) are rejected pre-mutation. **Residual, deliberately NOT claimed closed:** these caps bound what a request may DO, **not the parsing work an oversized message costs** — rmcp deserializes the whole `ClientJsonRpcMessage` off the transport before any handler runs, so only a transport-level byte cap would bound that and there is none. **`deny_unknown_fields` is still not a defence against DUPLICATE JSON KEYS** — `serde_json` collapses duplicates last-win while building the object, so the shadowed key is gone before any handler can observe it — but the defence is now the **D43 pre-parse byte scan at the transport**, not `deny_unknown_fields`: the frame is rejected in-band and never executed. **The unbounded-parse residual above REMAINS OPEN — D43 does not touch it, and in fact makes it worse:** the scan is a SECOND full `serde_json` pass over every line the reader keeps — whitespace-only, garbage and compat-ignored lines included (a STRICTLY EMPTY line is skipped before the scan, a whitespace-only one is not) — on the one per-frame path that has no length bound at all (rmcp's read is `max_length: usize::MAX`, while `max_request_bytes` is enforced only later, inside `call_tool`), so D43 DOUBLES that unbounded per-line cost rather than merely riding alongside it. A transport-level byte cap remains separate, unshipped hardening. Separately, a duplicated **envelope `id`** still yields NO response at all (D43 clause 6, tracked as `ub-cnv`). Also, the **request rate is bounded by a shared `Arc<Semaphore>(max_concurrent_requests)` chokepoint at the MCP handler gating the tool AND resource request surface** (`try_acquire` → `ErrorCode::RateLimited`, retryable — **in-band `CallToolResult` for tools, an `ErrorData` for resources** — D34); a malicious/buggy agent is bounded to its own workspace's data (no path escape, no host command execution); libsql remote credentials (when used) are **never** stored in `config.toml` — only via `UNBLOCK_*` env or OS keychain. Tie safe drift to `contract_version` (FR-12).
- **NFR-19 [compatibility] (D46)** — **On-disk backward compatibility: a released binary MUST open a database written by ANY earlier released binary, by migrating it FORWARD.** Minted at v1.0.1 because its absence — not the two missing columns — is what let a data-integrity tool ship a release that could not read its own predecessor's database while reporting `healthy`. **Reach (D46 clause (3)):** every physical shape that has ever existed, not GA-and-later only — the 5-column `comments` shape written before 2026-07-17, the current 7-column shape, and a stamped-`0` database that already carries tables. **The mechanism is the `PRAGMA user_version` ladder** (spine §3.2 `Storage::migrate`): opening a database at an earlier stamp migrates it, idempotently, and reports the honest `from`→`to` delta; opening one whose stamp LIES about its shape is a typed `SchemaMismatch` (exit 2) carrying a hint, never a silent read failure. **The obligation is directional, and the other direction is explicitly NOT promised:** a binary meeting a database stamped ABOVE its own version refuses it with the same coded error — correct behaviour, and not a D35 break, since D35's stable set is the MCP contract, the CLI lifecycle surface and the 0–8 exit codes, none of which is the on-disk schema (D46 clause (8)). *AC: **(1)** a database seeded at an earlier state — each shape named above — opens through the ONE config facade and reaches SCHEMA PARITY with a freshly created one (every table's column order plus the index set), with pre-existing rows intact and the added columns NULL. **(2)** No release may ship a schema change without a forward step: the D46 content pin makes the omission a BUILD error, not a field failure. **(3)** The proof must open a database it did NOT itself just create — the NFR-16 obligation that discharges this one; a suite that only round-trips freshly created databases proves nothing about this requirement and is exactly what was green while the defect shipped.*

### 8.2 Concurrency, async & data flow

- **Async everywhere** (tokio). The `Storage` trait is async (`async-trait`); libsql is an async client.
- **Supported v1 topology (D14 + D31):** each MCP client spawns its **own** `unblock mcp` (stdio = one server per
  client), so **multiple MCP servers per workspace is the NORMAL, SUPPORTED case** (D31 retires the D14 "one MCP-server
  process / multiple MCP servers unsupported" clause). v1 is **local single-workspace**: for one client, the engine
  serializes writes with an **in-process tokio `Semaphore`** (which now **composes above** the L2 advisory lock,
  D31) and reads use a fast path (WAL readers). **Cross-process** write serialization across the multiple MCP-server
  processes on one `unblock.db` (two editor windows, or a CLI `migrate`/`doctor` while the MCP server runs) is the RESTORED
  **`.unblock/.write.lock` advisory lock** (D31, an L2 storage primitive acquired at the whole-mutation scope),
  with `BEGIN IMMEDIATE` + native `busy_timeout` as the WAL-level backstop; `migrate` takes the
  exclusive lock (timeout=0 fail-fast) for the whole command, UNCONDITIONALLY (before the version check), the read-only `doctor` takes no lock.
- **Client registration & workspace discovery (D39):** because the supported topology is child-per-client (D31 —
  each MCP client spawns its OWN `unblock mcp` over stdio), how a client is REGISTERED determines how the child
  finds its workspace. Two config classes, opposite needs:
    - **Project-scoped, version-controlled config** (`.mcp.json` at the repo root, `.vscode/mcp.json`,
      `.cursor/mcp.json`) — shared across the team via git, so it MUST NOT carry a machine-specific absolute `--dir`.
      It needs no path at all: `unblock mcp` resolves the workspace from `CLAUDE_PROJECT_DIR` (injected by Claude
      Code into the child's process env, probed as a project ROOT), from `${workspaceFolder}` / the `cwd` field (VS
      Code, Cursor), or from the bounded cwd walk-up — precedence `--db` > `--dir`/`UNBLOCK_DIR` > `CLAUDE_PROJECT_DIR`
      > guarded cwd walk-up (D39). Note `${CLAUDE_PROJECT_DIR}` does NOT expand inside a hand-written `.mcp.json` (the
      var is in the spawned child's env, not the client's config-expansion namespace) — unblock reads it from its own
      process env, which is why it works with no author action. This is the topology the repo itself dogfoods
      (`mcp.json` passes no `--dir`).
    - **User-global config** (Claude Desktop's `claude_desktop_config.json` and its OS equivalents) — per-user,
      repo-blind, never committed, and often spawned with `cwd = $HOME`. It genuinely REQUIRES an absolute
      `--dir /abs/path/to/project/.unblock`, because no project-relative seam is available to it.
  The D39 walk-up guard (a `$HOME`/`.git` filesystem ceiling — a git-free existence probe, D13-safe) ensures a
  repo-blind spawn cannot silently bind an unrelated `.unblock/` far up the tree, and the D39 startup line (stderr,
  NFR-14) reports the bound dir so a mis-registration is observable rather than silent.
- **Multi-dev / cross-machine sharing is v1.3, not v1 (D15):** there, each dev keeps their own local `unblock
  mcp` pointed at a **shared libsql/Turso primary** (embedded replica: local reads, **writes delegated to the
  primary** → atomic ops like `claim` serialize there; reads are eventually-consistent per sync interval). That is
  how the swarm/multi-dev persona scales — **not** thousands of clients on one local MCP server. See `00-roadmap.md` §4.
- **Non-spin guarantee (NFR-3):** WAL + native `busy_timeout` (>0) + the in-process serialized writer + the
  **cross-process advisory `.unblock/.write.lock`** (D31) — no app-level spin: the native `busy_timeout` sleeps AND
  the `.write.lock` poll sleeps (`tokio::time::sleep`, 25 ms; never `File::lock()` blocking, never a busy-spin);
  defect-243 cannot recur. `failsafe`/retry only guard the optional remote/replica path.
- **Write flow (model B):** acquire engine write permit → mutate libsql (issue rows + transactional audit
  events) → optionally export to `issues.jsonl` (atomic temp+fsync+rename) if export is enabled. No git, no merge.
- **Read flow:** fast-path query against libsql (in-memory graph traversal via `petgraph` where needed) → render.
- **Shutdown (FR-17/D38):** a cooperative flag flips on signal; the engine flushes/closes libsql cleanly. The
  recorded signal decides the exit (`128+signo`) on the two cooperative-shutdown returns of `unblock mcp` (the run
  loop and `session.shutdown()`) — a run-loop/handshake `Err` seen after a signal is a diagnostic, not the exit
  code, while a pre-run-loop failure keeps its 0–8 code — and **no** return path may hang (D38).

## 9. MCP Surface Design (primary interface)

Designed deliberately rather than one-tool-per-CLI-command (to keep the client's tool list small — token cost
+ selection accuracy):

- **Tools** — actions, consolidated where natural (e.g. an `issue` tool with an `action` enum for
  create/update/close/reopen/delete; dedicated `claim`, `ready`, `dep`, `search`, `export`/`import`). Schemas via `schemars`.
- **Resources** — queryable state: `unblock://issues/{id}`, `unblock://issues/ready`, `unblock://issues/blocked`, `unblock://capabilities`, `unblock://schema`.
- **Prompts** — guided workflows: `triage`, `plan_next_work`, `close_with_suggestions`.
- **Errors** — domain errors map to MCP error data carrying `code`/`message`/`hint`/`retryable`, parallel to the CLI 0–8 exit codes.
- **Discovery** — `capabilities`/`schema` versioned by `contract_version` and pinned by the two-document `CONTRACT_HASH` drift gate (D22/D25).
- **Target:** keep v1 tool count small (favour consolidated tools + resources over a per-command explosion); record the count as a success metric (§14).

### 12.7 Workspace discovery — DEFINED (D39)
Workspace-dir discovery resolves through a single total precedence chain: **`--db` (derive) > `--dir`/`UNBLOCK_DIR` (`cli.dir`, one slot) > `CLAUDE_PROJECT_DIR` (project ROOT-probe) > guarded cwd walk-up** (D39). `CLAUDE_PROJECT_DIR` is honored as the host-injected project root (its `.unblock`/`_unblock` child is probed, no walk-up; a miss falls through) and is read via the injectable `EnvSource` seam (NFR-16). The cwd walk-up is BOUNDED (inclusive `$HOME`/`.git` filesystem ceiling — a git-free existence probe, D13-safe), closing the silent-wrong-DB hazard of an unbounded ascent, and `unblock mcp` reports the bound dir + winning tier on stderr at startup (NFR-14). Additive, non-semver (NO new `ErrorCode`, no contract bump); the normative wiring is spine §4.
